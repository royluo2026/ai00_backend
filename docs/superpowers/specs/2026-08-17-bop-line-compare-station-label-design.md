# BOP 线体对比候选项工位标识设计

## 目标

在“BOP 线体对比”插件的左右操作候选卡中显示操作所属工位，让使用者在对齐前能同时识别项目、操作、工位和 VPPS。

## 数据来源

- 操作通过 `parameters.parent_node_id` 提供所属节点 ID。
- 工位名称从已由 `craft.bop.execution_structure.get@1` 返回的受控执行结构 `nodes` 中，按 `node_id` 严格匹配解析。
- 不新增 Capability、REST 请求、数据库读取或插件权限。

## 展示规则

自动对齐、仅 VPPS 对齐和手工模糊候选统一使用三层候选卡：

1. 操作名称。
2. `工位名称 · station:<gid>`。如果 `parent_node_id` 已有 `station:` 前缀则不重复添加。
3. VPPS 与匹配方式或相似度。

回退规则：

- 有工位 ID 但执行结构中找不到名称：仅显示规范化后的 `station:<gid>`。
- 操作未提供 `parent_node_id`：显示“工位未提供”。
- 左右侧继续放在同一 `candidate-pair` 网格行中，新增文本不得破坏行对齐。

## 组件边界

- `candidate-view.js` 负责解析工位标识并生成候选卡标记。
- `app.js` 在读取 BOP 执行结构后保留节点索引，并在自动与手工候选渲染时传入对应侧的索引。
- 工位解析为纯函数，不读取 DOM，便于独立测试。

## 验收

- 左右自动对齐卡均显示各自工位名称和 ID。
- 手工模糊搜索的左右候选卡也显示工位。
- 工位名称缺失、节点不存在和 `parent_node_id` 缺失均有明确回退文案。
- 候选卡左右行仍对齐。
- Plugin SDK 全量测试通过，新版签名包通过正式插件升级链路在本机启用。
