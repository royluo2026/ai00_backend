# 数模仿真环境、PLMXML 工作文档与 VisMockup 同步总规格

**日期：** 2026-09-11

**状态：** 设计已由业务方向确认，书面规格等待用户最终复核

**领域 Owner：** Simulation；BOP 来源与回传由 Craft 共同负责

**客户端：** AI00 Windows x64 App、AI00 Connector、VisMockup 14.2

## 1. 规格效力与范围

本文收敛并修正以下规格中与当前业务决定相关的内容：

- `2026-09-08-digital-simulation-environment-redesign.md`
- `2026-09-09-simulation-environment-collaboration-versioning-design.md`
- `2026-09-10-simulation-three-layer-cache-version-diff-design.md`
- `2026-09-10-simulation-model-documents-alternate-hierarchy-design.md`

本文明确取代其中以下旧口径：

1. 仿真环境只对应一个模型文件或一棵 VM 树；
2. 插入 PLMXML 时默认丢弃备选层次结构；
3. 所有结构调整都等到一次全量同步后才影响 VisMockup；
4. 项目空间和个人项目空间作为仿真环境本身展示；
5. PLMXML 是 AI00 仿真环境的唯一权威存储。

未被本文修改的缓存、安全、Artifact、Connector 配对和 Capability 治理要求继续有效。

### 1.1 第一阶段目标

第一阶段交付一个可真实使用的文件型闭环：

```text
PLMXML/JT/BOP
  -> AI00 规范化内存工作模型
  -> 数据库实时草稿
  -> PLMXML 运行包
  -> VisMockup 受管文档
  -> Occurrence 控制与基础后置校验
```

工程师可以创建、打开或 Fork 个人仿真环境，插入 BOP、PLMXML、JT 和已有环境版本，编辑备选层次，保存不可变版本，将完整草稿同步到 VisMockup，导出 PLMXML 或完整环境包，并在授权和冲突检查后回传 BOP。

### 1.2 第一阶段明确不做

- 不直接从任意已打开的 VisMockup 文档自动取数；该入口先显示为不可用。
- 不建设通用 CAD 格式转换器。
- 不自动语义合并多个 BOP、PLMXML 或环境版本。
- 不向 Teamcenter 主数据回写。
- 不承诺所有 VisMockup 私有运行状态都能由标准 PLMXML 表达。
- 不要求 VisMockup 直接读取内存流；第一阶段继续物化实体文件。
- 不为每次树节点编辑重新生成和打开完整 PLMXML。

## 2. 统一业务概念

### 2.1 个人仿真环境

个人仿真环境是用户拥有的、可持续保存的仿真方案。它不是一个 PLMXML 文件、一个 VisMockup 窗口、一棵 VM 树或一个 BOP Repository。

一个个人仿真环境包含：

- 一个实时保存的当前草稿；
- 零个或多个不可变版本；
- 一组模型文档；
- 零个或多个可编辑备选层次结构；
- BOP、产品、Occurrence 和资源引用；
- 姿态、显隐、颜色、分析结果、问题和任务等 AI00 状态；
- 零个或一个当前可写 VisMockup 运行文档绑定。

用户可以创建多个个人仿真环境。一个环境在同一时间只允许一个可写运行实例；其他打开实例只读。

### 2.2 当前草稿与不可变版本

当前草稿是用户正在编辑的工作状态。有效修改通过 expected row version、幂等键和 Simulation 单域事务实时写入数据库。前端防抖只减少请求次数，不承担数据权威。

“保存仿真环境”把精确草稿冻结为不可变版本。保存版本不自动同步 VisMockup，也不自动回传 BOP。

### 2.3 模型文件

模型文件是不可直接编排的模型来源，包括：

- 主 PLMXML；
- 补充 PLMXML；
- JT；
- 从 BOP 投影中识别出的产品或资源模型引用；
- 后续阶段从 VisMockup 已打开文档取得的模型来源。

文件和模型主数据保持只读。AI00 保存文档逻辑身份、来源、版本、内容哈希、依赖、投影和本地/Artifact 引用，不把普通业务表当作文件字节仓库。

### 2.4 备选层次结构

备选层次结构是当前环境中可编辑的仿真组织视图。它可以由用户创建，也可以由 BOP 投影或 PLMXML 导入产生。

备选层次保存：

- 雪花 `hierarchy_gid`；
- 用户名称与排序；
- 父子节点关系；
- BOP 来源 Repository、空间、版本、Fork/投影证据；
- 产品 Occurrence 和资源放置引用；
- 姿态、显隐、颜色等仿真覆盖属性；
- 草稿版本、同步状态和审计信息。

备选层次不能包含另一个完整仿真环境。导入得到的层次只能成为当前环境的并列层次，不能递归形成环境套娃。

### 2.5 项目空间与个人项目空间

项目空间和受管个人项目空间是 Craft BOP 来源，不是 Simulation 仿真环境。它们不再作为“仿真环境库”中的环境展示，而是在“插入 BOP”时作为来源选择。

### 2.6 PLMXML

PLMXML 是 AI00 与 VisMockup 之间的导入、导出、运行物化、恢复和审计格式。AI00 数据库和规范化内存模型是协作语义的权威来源。

标准 PLMXML 不能表达的 AI00 状态由 AI00 Manifest 保存。纯 PLMXML 可以恢复其实际表达的模型和备选层次；完整环境包用于恢复 AI00 的全部可移植状态。

### 2.7 VisMockup 运行绑定

运行绑定显式指向：

```text
VisMockup 进程 -> 窗口 -> 文档 -> AI00 环境草稿/版本
```

“当前活动文档”只表示焦点，不能充当长期身份。所有控制命令必须携带明确的 `runtime_document_gid` 或等价的受控运行身份。

## 3. 核心不变量

1. AI00 草稿、已保存版本和 VisMockup 运行文档是三个独立状态。
2. 保存环境、同步 VisMockup、导出文件和回传 BOP 是四个独立动作。
3. 模型文件进入模型文件区；BOP 工艺骨架进入备选层次区；产品和资源不能重复混入两种结构。
4. 点击备选层次组节点时，控制集合以 AI00 当前草稿的完整叶子成员集合为准。
5. 只有 AI00 与 VisMockup 的成员集合和关键场景状态通过校验，层次才可标记为已同步。
6. 新模型尚未加载进 VisMockup 时，不得伪报对应节点可控。
7. 导入操作必须先明确用途；系统不得默认丢弃或默认合并备选层次。
8. BOP 插入必须绑定精确来源版本和复制深度。
9. BOP 回传必须先执行结构化三方 Diff、权限检查和用户确认。
10. 任何 `provider_failed` 必须保留稳定内部错误，同时向页面返回可行动的阶段、原因和重试信息。

## 4. 页面信息架构

### 4.1 第一列：个人仿真环境与资源

第一列上部为“个人仿真环境”，下部为“资源”。两个区域使用一致的折叠样式。

#### 个人仿真环境区

提供：

- 搜索与状态筛选；
- `新建`；
- 选中环境后的 `打开`；
- 选中环境或不可变版本后的 `Fork`。

列表行显示：

- 名称；
- 项目号；
- 当前版本；
- 最后保存时间；
- 草稿状态；
- VisMockup 同步状态。

“列表选中”和“当前已打开”必须有不同视觉状态。Fork 必须输入不与当前用户现有环境冲突的新名称，并记录来源环境、来源版本和内容哈希。

#### 资源区

显示设备、工装、工具、套筒等受治理资源。资源行只作为引用来源；拖入备选层次时创建 Simulation 放置关系，不复制或修改资源主数据。

### 4.2 第二列：当前仿真文档

第二列只有在一个个人仿真环境已打开时才可编辑。

顶部固定显示：

```text
个人仿真环境：W10 装配验证
当前草稿 · 基于 V3 · 最后保存 14:32
环境：草稿已自动保存 · 领先 V3 共 7 项
VisMockup：结构落后 3 项
```

这里“草稿已自动保存”表示数据库已持久化，“领先 V3”表示尚未冻结为新的不可变版本。页面不得把这两种状态合并成含糊的“未保存”。“保存仿真环境”仅在草稿内容哈希与最新不可变版本不同时启用。

#### 上部：模型文件

每个模型根显示：

- 显示名和格式；
- 主模型或补充模型角色；
- 来源与内容哈希；
- 文件生成/修改时间；
- `registered | loading | synced | pending_sync | version_changed | failed`；
- 外部依赖是否完整；
- 是否已在当前 VisMockup 运行文档中可定位。

#### 下部：备选层次结构

支持：

- 新建、改名、复制、归档层次；
- 节点展开、折叠、移动、排序和调整父子关系；
- 插入 BOP 工艺骨架；
- 放置产品 Occurrence 和资源引用；
- 显示 `synced | pending_members | full_sync_required | drifted | failed`；
- 点击组节点时控制全部有效叶子成员。

### 4.3 第二列操作栏

固定操作为：

```text
插入 ▾ | 保存仿真环境 | 同步到 VisMockup | 导出 ▾ | 回传 BOP
```

插入菜单：

- 插入 BOP；
- 插入 PLMXML；
- 插入 JT；
- 插入已有个人仿真环境版本；
- 插入 VisMockup 已打开文档——第一阶段灰色禁用，标注“第二阶段”。

导出菜单：

- 导出 VisMockup PLMXML；
- 导出完整环境包。

未打开环境时，第二列所有编辑、插入、保存、同步、导出和回传按钮禁用，并显示“请先新建或打开个人仿真环境”。

### 4.4 工程树视觉与显隐交互

模型文件树和备选层次树复用 VisMockup 工程树的高信息密度交互，但不复制其陈旧图标和视觉细节。

每一行从左到右固定为：

```text
[展开/折叠] [显隐复选框] [类型图标] [名称] [状态/数量]
```

三个控件的含义必须独立：

- 点击行背景：选择节点，不改变显隐，不展开层级；
- 点击方形加减号或展开箭头：只展开/折叠子节点；
- 点击显隐复选框：只改变该节点代表的完整 Occurrence 集合的显隐。

现有眼睛和删除线图标不再作为树节点显隐入口。显隐统一使用复选框：

- 选中：该节点的全部可控叶子 Occurrence 可见；
- 未选中：全部可控叶子 Occurrence 隐藏；
- 半选：部分叶子可见、部分叶子隐藏；
- 禁用：模型尚未加载、映射不完整或当前 VisMockup 文档不可控。

父节点状态必须从规范化工作模型的完整成员集合计算，不能只统计当前已展开或已渲染的子行。点击父节点复选框时，对完整叶子集合执行一次有界批量 COM 操作；部分失败时显示半选和明确失败数量，不将整次操作伪报成功。

树样式要求：

- 紧凑行高，目标为 22–26 px，避免卡片式大间距；
- 使用细竖线和横线表达父子层级；
- 逐级缩进固定，不因名称长度改变；
- 选中行使用浅蓝背景，焦点与悬停状态可以区分；
- 长名称单行截断，悬停显示完整名称、版本和来源；
- 状态图标和数量放在行尾，不挤占树名称的首要阅读位置；
- 复选框、展开控件和行选择均支持键盘操作及可访问名称。

类型图标采用 AI00 自己的简化图标体系：

| 对象 | 图标语义 | 建议色彩 |
|---|---|---|
| 模型文件区根 | 立方体/模型集合 | 蓝色 |
| PLMXML 文档 | 文档叠加立方体 | 蓝灰色 |
| JT 文档或叶子模型 | 单立方体 | 灰蓝色 |
| 产品总成/Occurrence | 装配立方体 | 暖黄色 |
| 备选层次区根 | 分支结构 | 紫色 |
| 单个备选层次 | 分叉节点 | 紫蓝色 |
| BOP 投影节点 | 工艺层级 | 蓝色 |
| 产品/资源放置引用 | 原类型图标叠加链接标记 | 原类型色加小型链接角标 |

图标用于区分语义，不承担显隐状态；显隐只看复选框。模型文件区和备选层次区必须能在不读标题的情况下通过根图标、色彩和放置引用角标快速区分。

## 5. 个人仿真环境流程

### 5.1 新建

用户输入环境名称并选择可选项目上下文。系统创建空草稿，不创建空的正式版本，不自动启动 VisMockup。

### 5.2 打开

打开环境会加载数据库草稿和最后一次完整缓存。若检测到另一个可写实例，当前实例以只读方式打开。切换环境前必须确认上一环境草稿已成功写入数据库；不依赖浏览器内存保存。

### 5.3 Fork

Fork 从选中的不可变环境版本创建新的个人仿真环境和草稿。名称必填且对当前用户唯一。Fork 保留来源版本、内容哈希、复制深度和可移植性报告，不继承原环境 ACL、运行绑定或设备身份。

## 6. 插入 BOP

### 6.1 来源选择

插入窗口必须选择：

- 来源项目；
- 来源项目空间或受管个人空间；
- 来源不可变 BOP 版本；
- 全部线体或指定线体；
- 复制深度；
- 新备选层次名称。

第一阶段每次插入 BOP 创建一个独立备选层次，不自动合并进现有层次。用户可以在插入后手工编排。

### 6.2 复制深度

复用 Craft 已有五档枚举与规范层级：线体 -> 工位 -> 岗位 -> 工序 -> 操作 -> 绑定。

| 复制深度 | 进入备选层次的正式投影 | 深度以下处理 |
|---|---|---|
| 全部复制 `all` | 全部 BOP 结构投影及允许引用的产品/资源绑定 | 无蓝图余项 |
| 复制到操作 `operation` | 线体至操作 | 产品/资源实例不复制，保留有序参考 VPPS |
| 复制到工序 `process` | 线体至工序 | 操作及以下保留为有序参考 VPPS |
| 复制到岗位 `role` | 线体至岗位 | 工序及以下保留为有序参考 VPPS |
| 复制到工位 `station` | 线体至工位 | 岗位及以下保留为有序参考 VPPS |

Simulation 复用 Craft 返回的只读、不可变投影和来源证据，不直接读取或复制 Craft 内部表。深度以内节点在 Simulation 中获得新的投影 GID，但继续绑定来源 BOP node/version/lineage；它们不是新的正式 Craft BOP 实例。

### 6.3 产品和资源剥离

选择“全部复制”时：

- 产品、PLMXML、JT 和资源模型来源登记到模型文件区；
- 备选层次只保存 BOP 工艺骨架和指向这些来源的放置引用；
- 不把模型节点作为普通 BOP 子节点再次复制；
- 删除放置不删除来源模型、资源或 Craft BOP。

### 6.4 插入预览

Apply 前必须显示并固定：

- 各层级节点数量；
- 产品、资源和绑定数量；
- 深度以下参考 VPPS 数量；
- 无权读取、失效或不可移植引用；
- 来源版本、内容哈希、复制深度和预览有效期。

Apply 必须复验相同 plan hash、来源版本和权限。预览变化后禁止沿用旧确认。

## 7. 插入 PLMXML

### 7.1 用途必须显式选择

选择文件并完成安全解析后，用户必须选择以下一种用途。没有默认值，未选择不能继续。

#### 恢复为个人仿真环境

- 创建新的个人仿真环境；
- 导入模型文件和全部可识别备选层次；
- 恢复 PLMXML 可表达的姿态、显隐、颜色和引用关系；
- 如果存在哈希匹配的 AI00 Manifest，则恢复完整 AI00 状态；
- 如果缺少 Manifest，则报告无法恢复的 AI00 专有状态。

该动作属于第一列“新建”旁的导入入口，不要求先打开现有环境。

#### 插入模型及选中的备选层次

- 先列出文件中所有可识别备选层次；
- 用户明确勾选需要导入的层次；
- 模型进入当前环境的模型文件区；
- 所选层次以新的 `hierarchy_gid` 成为当前环境的并列层次；
- 名称冲突时要求用户在预览阶段确定新名称。

#### 仅插入模型

- 只导入模型文档、依赖和产品 Occurrence；
- 明确丢弃文件中的备选层次投影；
- 原始文件仍作为不可变来源 Artifact 保存，以便审计和重新导入。

### 7.2 防止环境套娃

数据模型不允许“环境包含环境”。导入已有环境版本或 PLMXML 时，只能展开为：

```text
当前环境
├─ 模型文档来源
└─ 零个或多个并列备选层次
```

不得保存：

```text
当前环境 -> 导入环境 -> 导入环境 -> ...
```

系统必须：

- 保存来源环境/文件、来源版本、来源层次和内容哈希；
- 为导入层次生成新的服务端雪花 GID；
- 检测同一文件哈希和来源层次的重复导入；
- 检测 PLMXML 外部依赖回路；
- 将共同依赖按内容哈希去重；
- 对无法安全展开的依赖循环返回 `model_document_dependency_cycle`。

### 7.3 导入预览

预览至少显示：

- 文件名、大小、哈希、生成时间和 PLMXML 版本；
- 产品/Occurrence 数量；
- 备选层次名称和节点数量；
- 外部 PLMXML/JT 依赖；
- 重复内容、缺失依赖和未知扩展；
- 所选导入用途及最终将创建的对象数量。

## 8. 插入 JT 和已有环境版本

### 8.1 JT

JT 作为主模型或补充模型登记。JT 内部结构不由 AI00 猜测；第一阶段以 VisMockup 打开后的受控回读或可用解析证据形成 Snapshot。JT 没有备选层次导入选项。

### 8.2 已有个人仿真环境版本

插入不可变环境版本时沿用 PLMXML 的用途选择，但只允许：

- 插入模型及选中的备选层次；
- 仅插入模型。

如果用户要完整继承该版本，应使用第一列的 Fork，而不是在当前环境中嵌套另一个环境。

## 9. 规范化内存工作模型

### 9.1 必须在第一阶段建立

第一阶段不能只在需要导出时拼接 XML。AI00 必须维护结构化工作模型，至少包含：

- Environment、Draft 和 immutable Version；
- ModelDocument 及依赖图；
- Occurrence 及稳定映射证据；
- AlternateHierarchy 和节点；
- Placement；
- BOP、产品和资源来源引用；
- 姿态、显隐、颜色；
- RuntimeBinding；
- 未识别但需保真的扩展证据；
- 当前内容哈希和同步基线。

模型只在当前打开环境、解析、Diff 或同步期间驻留内存。数据库保存权威草稿；Connector SQLite、前端 IndexedDB 和内存对象均为可重建缓存。

### 9.2 身份

所有服务端业务实体使用雪花 GID。PLMXML 内部 ID、文件路径、COM handle、窗口句柄、进程 ID 和树路径都是技术标识，不能作为长期业务主键。

Occurrence 映射至少绑定文档 GID、Snapshot GID、内容指纹、PLMXML/VisMockup 实例证据和稳定来源线索。仅名称相同不能自动认定为同一实例。

## 10. VisMockup 同步策略

### 10.1 两条同步路径

#### 轻量实时路径

以下操作在来源模型已经加载、Occurrence 映射明确时立即调用 COM：

- 选择；
- 高亮；
- 显示与隐藏；
- 颜色；
- 定位和视角；
- VisMockup COM 已验证支持的备选层次成员增加、删除、移动或改名。

#### 显式全量路径

点击“同步到 VisMockup”处理：

- 新增、删除或替换模型文件；
- 大批量 BOP 插入；
- 依赖变化；
- 增量同步失败；
- 运行文档漂移；
- 需要重新生成完整备选层次的变化。

全量同步从精确草稿生成一个顶层 PLMXML 和依赖 Manifest。第一阶段在受控临时目录物化文件，并按以下顺序安全切换：

1. 保留当前 VisMockup 文档不动；
2. 将新运行包打开为新的 AI00 受管文档；
3. 回读文档、模型集合和关键 Occurrence，执行控制抽样；
4. 验证成功后切换运行绑定；
5. 只有旧文档同样由 AI00 管理、没有 drift 且没有未确认操作时，才关闭旧文档；否则保留旧文档并提示用户处理。

不得无提示覆盖工程师自行打开且可能有未保存修改的外部文档。

### 10.2 组节点控制语义

假设：

```text
A = [B, C, D]
```

用户把已经加载的 E 放入 A 后：

1. AI00 草稿立即变为 `A = [B, C, D, E]`；
2. 数据库写入成功后，AI00 尝试轻量同步 A 的成员变化；
3. 点击 A 时，AI00 根据当前草稿展开叶子 Occurrence，并对 B、C、D、E 执行批量控制；
4. 只有 VisMockup 成员集合回读也包含 E，A 才标记为已同步。

若 E 的模型尚未加载：

- E 可以保存在草稿；
- A 显示“含 1 个待同步成员”；
- E 的三维操作禁用；
- A 不得显示为完整同步；
- 完成一次全量同步后再校验并启用 E。

若 COM 无法增量修改 VisMockup 原生备选层次，AI00 页面仍按当前叶子集合正确控制右侧三维，但原生 VisMockup 层次显示 `full_sync_required`，不得伪报一致。

### 10.3 同步预览和状态

同步前显示：

- 新增/移除/替换模型数；
- 新增/删除/移动层次节点数；
- 待同步成员数；
- 依赖与可移植性检查；
- 目标 VisMockup 文档和当前绑定状态。

同步状态至少包括：

- `not_bound`
- `pending_sync`
- `incremental_syncing`
- `full_sync_required`
- `materializing`
- `synced`
- `drifted`
- `failed`
- `outcome_unknown`

COM 超时或连接中断后必须先查询 operation 和真实后置状态。无法证明成功时保持 `outcome_unknown`，不能盲目重复插入。

## 11. 保存与导出

### 11.1 保存仿真环境

“保存仿真环境”冻结不可变版本，绑定：

- 环境和版本 GID；
- 草稿内容哈希；
- 模型文件及依赖哈希；
- BOP 来源版本与复制深度；
- 备选层次、Placement 和映射；
- 编解码算法版本；
- 创建人和时间。

保存数据库版本不等于已经能由 VisMockup 完整恢复。只有完成真实物化、回读和控制验证的精确版本才能获得独立的 `runtime_verified` 状态。

### 11.2 导出 VisMockup PLMXML

导出当前精确草稿或用户选定的不可变版本。输出保证目标 VisMockup 可以消费，但只承诺已声明的 PLMXML 可表达语义，不承诺 XML ID、属性顺序或字节完全一致。

文件记录或伴随：

- 环境/版本 GID；
- 项目号；
- 内容哈希；
- 生成时间；
- 编解码算法版本；
- 无法表达项报告。

### 11.3 导出完整环境包

完整环境包包含：

- 顶层 PLMXML；
- 外部 PLMXML/JT 等依赖；
- AI00 Manifest；
- 每个文件的哈希、大小、媒体类型和可移植性；
- BOP/资源引用证据；
- 无法表达项报告。

第一阶段的完整环境包采用普通目录，不新增私有压缩格式：

```text
环境名称-版本/
├─ environment.plmxml
├─ ai00-manifest.json
└─ dependencies/
   ├─ *.plmxml
   └─ *.jt
```

用户可以直接用 VisMockup 打开顶层 `environment.plmxml`。AI00 从该文件恢复时只读取同目录中经 Manifest 列出且哈希匹配的依赖，不扫描或信任目录中的其他文件。

重新导入时，Manifest 存在且哈希匹配则恢复完整 AI00 状态；只有 PLMXML 时只恢复其中实际可表达的内容，并明确报告缺失项。

## 12. BOP 回传

回传仅对具有明确 BOP 来源的备选层次开放。流程为：

```text
来源 BOP 不可变版本
        + 当前 BOP head
        + 当前备选层次投影
        -> 三方结构 Diff
        -> 权限与资源引用复验
        -> 用户确认
        -> Craft Capability 写入
```

预览必须显示新增、删除、移动、属性变化、来源 head 前进、节点冲突、资源版本冲突和无权限节点。

Simulation 不直接写 Craft 表。回传失败不回滚或破坏 Simulation 草稿；成功后记录 Craft 返回的目标版本、结果哈希和审计身份。

## 13. 后端实现边界

### 13.1 优先复用

优先补全当前已有实现：

- PLMXML 安全流式解析与投影；
- `EnvironmentRuntimeModel` 和 codec；
- 环境模型文档、层次和 Placement Repository；
- `simulation.plmxml.environment.import@1`；
- `simulation.plmxml.environment.export@1`；
- `simulation.environment.runtime_package.prepare@1`；
- Connector plan、runtime session 和 operation outcome；
- Craft BOP Repository/space fork preview、apply 和 projection。

不得另建一套平行的 PLMXML 解析器、环境表或绕过 Gateway 的页面 API。

### 13.2 Capability 候选

实施前必须从运行 Registry/Catalog 重新核对版本、GID、Provider、消费者和合同。当前候选业务效果为：

| 业务效果 | Capability 候选 |
|---|---|
| 登记、查询、解除环境模型文档 | `simulation.environment.model_document.add/search/remove@1` |
| 创建、读取、修改、归档备选层次 | `simulation.environment.alternate_hierarchy.create/search/get/update/archive@1` |
| 创建、移动、移除放置引用 | `simulation.environment.placement.create/move/remove@1` |
| 预览和执行 PLMXML 导入 | `simulation.plmxml.environment.import.preview/apply@1`，是否需要升版由现有合同核对决定 |
| 保存不可变环境版本 | 复用或补全现有 workspace version create 能力 |
| 预览、执行、查询运行同步 | `simulation.environment.runtime_sync.preview/apply/get@1` |
| 预览、执行、查询 BOP 回传 | 由 Simulation 准备投影，Craft 执行 owner 写能力 |

PLMXML import 合同必须显式包含：

- `purpose`: `restore_environment | insert_model_and_selected_hierarchies | insert_model_only`；
- `selected_hierarchy_refs`：仅第二种用途允许且必填；
- 目标 environment/draft expected version；恢复新环境时不允许目标环境；
- 原始 ArtifactRef、内容哈希和解析报告；
- 唯一幂等键。

BOP 插入合同必须携带 `source_version_gid`、线体选择、`fork_depth`、目标环境/草稿版本、预览/plan hash 和幂等键。

### 13.3 Adapter 技术 operation

以下是 Connector/VisMockup Adapter 技术 operation，不因对应 COM 方法而自动成为用户业务 Capability：

- 文档打开和受管替换；
- 模型插入；
- Occurrence 批量选择、显隐、高亮和着色；
- 备选层次成员增加、移除、移动和回读；
- 文档结构摘要与后置校验；
- 后续阶段的文档发现和导出。

所有 operation 必须来自受签名、过期时间有限且绑定 actor/device/runtime document 的 Connector plan。

## 14. 前端实现边界

前端不得自行推断复制深度、成员集合、权限或同步结果。页面消费 Capability 返回的预览、状态和稳定错误。

建议按现有页面最小拆分为：

- 环境列表与环境操作；
- 资源列表；
- 模型文档树；
- 备选层次树；
- 插入预览对话框；
- 草稿/版本/运行同步状态条；
- 同步、导出和回传操作区。

长操作必须页内显示阶段和耗时。禁用入口应说明前置条件或计划阶段，不使用无反馈按钮和循环弹窗。

## 15. 权限、安全与数据边界

- 个人仿真环境默认只允许 owner 写；明确授权的读取规则继续沿用现有 Simulation 可见性合同。
- BOP 来源读取、产品和资源引用分别通过 Owner Capability 授权，不能由 Simulation 根据页面角色猜测。
- BOP 回传使用 Craft 的节点/线体资源范围权限；super admin 也必须走相同受审计写能力。
- 本地绝对路径只保存在 Connector 本机受控 token/缓存中，不进入普通共享业务表或日志。
- PLMXML 解析继续禁止 DTD、外部实体和 XInclude，并执行字节数、元素数、深度、字符串、引用数和解析时间上限。
- 本地文件 hash、运行包依赖 hash 和 Manifest hash 必须在使用前复验。
- 写操作使用 expected version、唯一幂等键、确认策略和审计事件。

## 16. 性能与缓存

- 页面优先显示最后一次完整缓存，再异步刷新。
- 显示层级只控制渲染，不控制采集、解析或缓存深度。
- PLMXML 使用安全流式解析，不构造无界 DOM。
- 当前打开环境可维护规范化内存图和索引；关闭后可释放并从数据库重建。
- 组操作通过预计算/增量维护的层次成员索引解析叶子 Occurrence。
- 高频控制走直接 COM 批量操作，不走完整 PLMXML。
- 全量运行包按内容哈希缓存；相同内容可复用实体文件。
- 第一阶段不引入常驻通用缓存服务或新的第三方依赖。

## 18. 第一阶段验收场景

### 环境和页面

1. 未打开环境时第二列操作全部禁用且原因明确。
2. 用户可以新建、打开和 Fork 个人仿真环境；Fork 名称冲突被拒绝。
3. 页面刷新或 App 重启后恢复数据库中最后确认的草稿。
4. 同一环境第二个可写实例被降为只读。

### BOP 插入

5. 五种复制深度分别产生正确的层级边界。
6. 用户可以选择全部线体或指定线体，未选择范围不能 Apply。
7. 深度以下内容不会伪装成正式 BOP 节点。
8. 全部复制时产品和资源进入模型文件区，备选层次只保存放置引用。
9. 插入预览数量、来源版本、plan hash 与最终落库结果一致。

### PLMXML/JT 导入

10. PLMXML 导入没有隐式默认用途，用户必须选择一种。
11. “恢复环境”保留全部可识别备选层次，并报告缺失的 AI00 专有状态。
12. “插入模型及所选层次”只导入勾选层次。
13. “仅插入模型”明确不投影备选层次，但保留原始 Artifact。
14. 同一内容和层次重复插入被识别，不形成套娃。
15. 外部依赖环路、缺失文件和 hash 不符返回稳定错误。
16. JT 插入后只有在 VisMockup 能定位实际模型时才标记可控。

### 层次与三维控制

17. A 初始包含 B、C、D，加入已加载 E 后，AI00 点击 A 控制 B、C、D、E。
18. E 未加载时 A 显示待同步成员，E 的三维操作禁用。
19. COM 增量层次更新失败时保留草稿并标记全量同步，不伪报成功。
20. 显隐、高亮、选择和颜色操作不生成完整 PLMXML。
21. 树节点行选择、层级展开和显隐复选框互不触发其他动作。
22. 父节点复选框能够准确显示全选、未选和半选状态，并基于未展开的完整后代集合执行控制。
23. 模型尚未同步或映射不完整时复选框禁用并给出页内原因。
24. 模型文件、产品总成、备选层次、BOP 节点和放置引用使用可区分且一致的图标语义。

### 保存、同步和导出

25. 自动保存草稿与保存不可变版本状态明确区分；保存环境只创建不可变版本，不自动同步或回传。
26. 多次重编辑可以累计后只执行一次全量同步。
27. 全量同步失败不损坏最后可用 VisMockup 文档和 AI00 草稿。
28. 导出的 PLMXML 可由真实 VisMockup 打开并定位关键 Occurrence。
29. 完整环境包重新导入后恢复模型集合、备选层次、BOP 来源和 AI00 Manifest 状态。
30. 只有完成物化、回读和控制抽样的精确版本才产生 runtime verification 证据。

### BOP 回传

31. 无 BOP 来源、无权限或有未解决冲突时回传按钮不可执行。
32. 回传前显示三方 Diff，确认绑定精确预览和目标 head。
33. Craft head 在预览后变化时 Apply 失败并要求重新预览。
34. 回传失败不丢失个人仿真环境草稿。

## 19. Capability 治理记录

### Change classification

- 类型：新 Capability、experimental 合同兼容/升版候选和实现修复的组合。
- 原因：新增个人仿真环境文件闭环、显式 PLMXML 导入意图、运行同步和 BOP 投影/回传业务效果；同时修正已有单文档和隐式导入语义。

### Authoritative context inspected

- 已检查 Simulation 现有 PLMXML projection/codec、环境文档、层次、Placement、runtime package、Connector plan 和测试路径。
- 已检查 Craft BOP Repository Fork 的五档复制深度、projection 和 preview/apply 合同。
- 已检查 2026-09-08 至 2026-09-10 的相关规格。
- 运行 Registry/Catalog、精确 Capability GID、当前消费者图和真实 Provider 绑定必须在实施前重新读取，当前仍为 `unverified`。

### Reuse、atomicity 与 ownership

- Simulation 拥有环境、草稿、版本、模型投影、备选层次、Placement、PLMXML 转换和运行同步。
- Craft 拥有 BOP Repository、空间、版本、Fork 投影和回传写入。
- Base Artifact 拥有不可变文件字节和 ArtifactRef；Connector 仅保管本机路径 token 和执行状态。
- 导入、保存、同步、导出和回传具有不同授权、失败、幂等和审计语义，不能合并为一个万能 Capability。
- 优先补全现有 experimental 能力；不得静默扩大 stable 合同。
