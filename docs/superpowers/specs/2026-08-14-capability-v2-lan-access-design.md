# Capability V2 局域网访问设计

## 目标

让本机测试服务器上的 `AI00Backend-CapabilityV2` 可由团队开发者通过
`http://pc-pc2l7vve:8094/web/` 访问，并保证飞书扫码登录回到同一服务。

## 范围与约束

- 仅调整 `AI00Backend-CapabilityV2`，不修改旧服务。
- 服务端口保持 `8094`，监听地址由 `127.0.0.1` 改为 `0.0.0.0`。
- Windows 防火墙仅允许公司域网络（`DomainAuthenticated`）中的本地子网访问
  TCP 8094，不开放 Private 或 Public 网络范围。
- 不开放数据库、MinIO 或其他内部服务端口。
- 飞书 OAuth 回调统一为
  `http://pc-pc2l7vve:8094/auth/feishu/callback`。
- 运行时配置和启动脚本修改前必须创建带时间戳的本机备份；备份不得提交。
- 密码、令牌及其他敏感配置不得输出、记录或提交。

## 运行结构

团队浏览器通过主机名 `pc-pc2l7vve` 解析测试服务器的局域网地址，连接 TCP
8094。Windows 防火墙先限制配置文件为 Domain、来源为本地子网，随后 Uvicorn
在所有本机网卡上接收请求。前端与后端使用同一来源，因此普通 API 请求不需要
额外跨域授权。

飞书扫码登录由 8094 服务生成 OAuth 登录地址。飞书完成授权后，浏览器回到
同一主机名和端口的 `/auth/feishu/callback`，再由登录页轮询 8094 获取登录结果。

## 配置变更

1. 将 Capability V2 启动脚本中的 Uvicorn `--host` 设置为 `0.0.0.0`。
2. 将 `.env.v2.runtime` 中的 `FEISHU_REDIRECT_URI` 设置为设计中的 8094 回调。
3. 创建仅限 Domain 网络、本地子网、TCP 8094 的入站防火墙规则。
4. 在飞书开放平台登记完全相同的重定向 URL；若平台尚未登记，服务端变更后
   登录会明确停在飞书的回调校验错误，不应回退到旧端口。
5. 仅重启 `AI00Backend-CapabilityV2`。

## 故障处理与回滚

- 若服务启动失败，恢复启动脚本备份并重启新服务。
- 若飞书拒绝回调，保留 8094 服务访问能力，完成飞书开放平台白名单后重试；
  不恢复旧的 8082 回调。
- 若局域网暴露范围超出本地子网，立即禁用新防火墙规则并恢复仅监听
  `127.0.0.1`。
- 所有回滚操作仍不得影响旧服务。

## 验收

- `netstat` 显示 TCP 8094 监听于 `0.0.0.0`，且进程属于 Capability V2 服务。
- 本机通过 `127.0.0.1:8094` 与 `pc-pc2l7vve:8094` 均能访问 `/health` 和
  `/web/`。
- 从同一局域网的另一台开发电脑可访问上述主机名入口。
- `/auth/feishu/login-url` 返回的 `redirect_uri` 精确等于设计值。
- 完成一次飞书扫码登录，回调、轮询及主页进入成功。
- 服务状态为 Running、启动类型为 Automatic；新启动周期日志无 Traceback、
  静态资源 404 或认证回调错误。
