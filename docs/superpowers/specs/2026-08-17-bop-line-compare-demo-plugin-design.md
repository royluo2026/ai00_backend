# 双车型 BOP 线体对比演示插件设计

## 1. 目标

新增一个真正可安装、可启用、可从工作区打开的演示插件，用于对比两个车型的 BOP 线体，并直观展示插件如何声明、调用和编排 Capability V2。

插件优先证明以下能力，而不是建设生产级差异分析系统：

1. 插件只通过受控 Mount 访问业务能力，不直连 REST、数据库或宿主内部对象。
2. 插件可以将多个领域能力编排成一个完整业务步骤。
3. 同一插件可以组合工艺、零件和工具材料形成新的业务体验。
4. 用户能看见本次调用了哪些 Capability、每一步为何调用以及结果如何参与最终展示。

## 2. 产品范围

插件暂定名称为“BOP 线体对比”，插件 ID 为 `devteam.ai00.bop-line-compare`。

首版只读，不保存历史，不新增插件业务表，不提供导出、审批或写回。插件页面包含：

- 左右车型项目、BOP 版本和线体选择。
- 三种操作匹配方式。
- 工艺、零件、工具三个对比视图。
- 可展开的 Capability 编排与调用结果面板。
- 局部错误与降级说明。

## 3. 操作匹配

### 3.1 VPPS 精确对齐

当左右操作的非空 VPPS 完全相同时，形成精确匹配。该方式优先级最高，结果标记为“VPPS 精确匹配”。

### 3.2 描述模糊对齐

当 VPPS 缺失或不一致时，插件对操作名称、可用描述和所属工位进行轻量文本归一化与相似度排序。结果必须标记为“描述模糊匹配”，并显示匹配依据，不得伪装成受控业务关系。

首版使用确定性的本地文本算法，不调用大模型：统一大小写和空白、移除常见标点、计算字符二元组和关键词重合度，并用工位名称作为次要加权信息。

### 3.3 手工输入模糊匹配

用户输入自然文字，例如“副车架拧紧”。插件分别在左右选定线体的操作集合中排序候选，双列展示结果。用户选择左右各一个候选后形成手工对比对，结果标记为“手工选择”。

零件与工具不依赖 VPPS。它们始终以已选中的左右操作为上下文，根据操作关联引用比较共同项、左侧独有项和右侧独有项。

## 4. Capability 编排

插件声明且仅调用以下现有能力：

1. `base.project.search@1`：搜索左右车型所对应的项目引用。
2. `craft.bop.version.list@1`：按项目发现可用 BOP 版本。
3. `craft.bop.execution_structure.get@1`：读取已发布 BOP 的确定性层级、线体、工位、操作、VPPS 和关联引用。
4. `craft.bop.work_package.get@1`：将完整 BOP 投影为选定线体的有界工作包，获得操作、零件和工具引用。
5. `craft.bop.linked_parts.get@1`：补充零件编号、名称和使用位置。

不使用 `craft.bop.version.compare@1` 作为主路径，因为首版比较的是两个车型中的特定线体和操作，而不是完整版本变更集。

调用流程：

```text
搜索项目
  -> 获取项目的 BOP 版本
  -> 读取 BOP 执行结构并选择线体
  -> 获取左右线体工作包
  -> 获取左右 BOP 关联零件详情
  -> 在插件沙箱内匹配操作并生成工艺/零件/工具对比
```

插件底部的“本次编排”面板逐步显示：Capability ID 与主版本、业务目的、调用状态、耗时、返回条目摘要以及是否参与当前结果。不得显示令牌、内部错误堆栈或敏感原始载荷。

## 5. 界面与交互

页面采用高对比深色界面，不使用白底灰字。

顶部是左右两个选择区，每侧按“项目 -> BOP -> 线体”逐级选择。更换上游选择时清空该侧下游状态和过期结果。

中部包含一个搜索输入和三种匹配入口：

- “自动对齐”先做 VPPS 精确匹配，再提供描述模糊候选。
- “仅看 VPPS”只展示精确对齐结果。
- 用户输入文字后，左右列独立返回模糊搜索候选。

确认操作对后，下方以固定左右列展示：

- 工艺：名称、VPPS、工位、顺序、前置操作、可用参数和差异。
- 零件：共同零件、左右独有零件、编号/名称、使用位置和受控引用。
- 工具：共同工具、左右独有工具、关联操作和受控引用。现有契约缺少名称时明确显示引用，不虚构名称。

## 6. 状态与错误

- 每侧请求使用递增请求序号；旧请求完成后不得覆盖新选择。
- 一侧失败时保留另一侧结果，并在失败侧显示 Capability 错误码和可读说明。
- 未发布 BOP 无法使用正式执行结构时，标记为不可比较并提示选择已发布版本。
- 未找到同 VPPS 不属于错误，正常进入模糊匹配或手工选择。
- 工具只有引用而无详情属于契约能力边界，界面如实降级。

## 7. 演示数据与验收

为保证现场演示可重复，验收工具创建或复用两套明确属于不同车型项目的已发布 BOP，每套至少包含：

- 一条可选择线体和一个工位。
- 一个 VPPS 相同、参数或顺序不同的操作。
- 一个 VPPS 缺失但描述相近的操作。
- 一个共同零件和左右各一个独有零件。
- 一个共同工具引用和左右各一个独有工具引用。

最小验收路径：安装 -> 启用 -> 从工作区打开 -> 选择左右项目/BOP/线体 -> VPPS 精确对齐 -> 描述模糊对齐 -> 手工输入搜索 -> 切换工艺/零件/工具 -> 查看 Capability 编排 -> 停用后入口消失。

## 8. 测试边界

自动化测试覆盖：

- 三种匹配路径及优先级。
- 零件和工具的共同/独有集合计算。
- 一侧失败和过期请求抑制。
- Manifest 权限与实际调用一致。
- 禁止直接网络、Cookie 和宿主 DOM 访问。
- 编排面板不泄露敏感载荷。

本轮不追求复杂语义匹配准确率、跨 BOP 全量差异、AI 推理、历史持久化和报告导出；这些作为插件系统后续扩展示例保留。
