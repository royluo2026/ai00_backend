# AI00 在线 VisMockup 环境同步与双向文档切换更改规格

版本：0.3，2026-09-14。状态：主设计已获用户同意实施；补充重复插入实例、时间来源与从现有文档创建环境。不是已实现或已发布声明。

规范性专项补充：[大规模结构同步规格](2026-09-14-large-structure-sync-design.md)。自审记录：[覆盖与缺漏审查](2026-09-14-sync-design-self-review.md)。主规格与专项规格应一起评审和实施。

## 1. 更改分类与业务目标

分类：现有 Simulation 模型来源、运行时绑定与同步的架构调整。优先兼容扩展；涉及现有 Capability 输入、业务效果或执行位置变化时，逐项判定是否需要新 major，不在此擅自复用旧批准。

目标：以在线模型为日常运行来源，在 AI00 与同一 VisMockup 进程内的文档之间建立明确绑定。切换环境与切换文档互相联动；备选层次及产品引用双向增量同步；AI00 持续保存可恢复定义和带时间的结构观测。

本规格优先于 2026-09-10 模型文档规格中“每个环境通过顶层 PLMXML 作为唯一运行入口”的设计，以及 2026-09-14 旧计划中“所有首次打开均从模型 Artifact 重建”的假定。PLMXML 保留本地来源、显式快照、导入导出用途，不再是在线文档日常读取中转。

### 1.1 第一期范围

- 在线 CPS 原始产品结构直接读取、分批补取、完整性标识及时间化观测。
- 在线来源和本地文件来源明确区分；一个环境允许多个来源。
- 一个环境在一个 Connector 运行会话中最多绑定一份存活的运行文档；一份运行文档最多绑定一个环境。
- 环境选择、AI00 文档选择器和 VisMockup 自身活动文档切换互相协调。
- 绑定范围内 AH 的创建、重命名、移动、排序、删除，以及产品引用的新增、移动和移除。
- 手工变更回收、冲突提示、异常退出恢复、大批量分片执行。

不回写或回收原始 CPS 结构、模型几何、姿态变换、剖切、标注等。不可将本期恢复能力宣传为完整替代 VFZ 的所有功能。

## 3. 复用、原子性与归属

复用 Simulation 环境、模型来源、AH、placement 和版本存储，不创建第二份可写业务树。IndexedDB/Connector 缓存只保存可重建投影；已有只读缓存不自动获得离线写权限。

| 内容 | Owner 与边界 |
| --- | --- |
| 环境、来源关联、AH、引用、冲突及结构观测 | Simulation |
| BOP 原始节点和版本 | Craft；通过既有合同形成仿真骨架，不回写 Craft |
| 本地制品及显式快照字节 | 既有 Artifact/文件 Provider |
| 当前文档对象、CPS/AH key、原生执行 | Connector VisMockup Adapter |
| 文档选择器和画面挂接 | Simulation UI 与 Electron 宿主；不持有数据库写规则 |

业务效果必须独立区分：建立绑定、激活绑定文档、持久化观测、接受冲突解决、执行差异。不得以一个任意命令万能 Capability 包装所有原生方法。先检索现有能力，再补缺失合同；本规格不虚构已注册 ID/GID。

发现的缺口：当前原生入口依赖研究用地址；在线来源稳定身份与历史配置重开未验证；现有文档操作偏向 ActiveDocument，缺少贯穿全链路的环境文档会话范围；运行包物化不能直接承接高频 AH 变更。

## 4. 实现边界与详细设计

### 4.1 四类身份，不混用

1. **环境身份**：tenant/actor/workspace_gid，含权限与版本。
2. **来源身份**：online 或 local_file。在线包含来源系统、对象身份、可获取的修订/配置与实例定位信息；本地包含受控链接、文件指纹、依赖及可选 ArtifactRef。
3. **运行文档会话身份**：Connector 设备、进程启动代次、文档实例标识和 session_epoch。HWND、指针、CPS key 仅属于该代次。
4. **模型插入实例身份**：每次实际插入独立的 `insertion_instance_id`，与来源身份、文件名、路径、内容哈希和时间戳都不同。两个实例可共享来源和内容缓存，但不可共享引用身份。

同名文档不等于同一文档；同一零件编号不等于同一装配实例。稳定实例身份不足时标记 ambiguous/session_only，不自动跨会话重新绑定。

一环境的多个模型来源可以组合在一份运行文档中。“一个环境一文档”不等于“一个环境一个来源文件”。文档反向命中多个绑定是数据冲突，禁止任取一个。

#### 4.1.1 重复插入与时间

- 同一 PLMXML/JT 路径、同名在线模型、相同内容都允许重复插入。AH 产品引用必须携带来源、插入实例和实例内 occurrence 三部分；禁止只按名称或来源哈希命中。
- 已确认旧模型表有 `(workspace_gid,source_identity_hash)` 唯一约束，属于来源记录，不能直接当作重复插入实例。实例存储需与来源分开；不得再把来源哈希或会话内数组位置当实例主键。稳定映射不足时标记 ambiguous，不按顺序猜测。
- `inserted_at` 仅记录有证据的插入时间，UTC 存储、界面按本地时区展示。AI00 插入命令同时保留调用起止时间；如原生端不能提供精确插入时刻，显示确认插入的时间并标明 provenance，不声称是原生精确时间。
- 手工插入的历史实例若无法查到真实时间，`inserted_at=null`，以 `first_seen_at` 表示 AI00 首次观察时间。重复扫描不刷新首次发现时间；删除后再次插入生成新实例。
- `captured_at_start/end` 属于结构观测；来源版本和内容指纹用于内容比较。上述时间不互相替代，插入时间也不能证明内容新旧。
- Connector 现有计划日志按签名 PlanId 防重放；不能改成按文件路径防重放，也不能仅凭 StepId 去重不同计划。未知执行结果先读回，不自动再次插入。
- 旧 `vismockup.model.insert@1` 会跳过同路径，且原生读回只查同路径存在。新的实例插入业务效果不得暗改旧合同：版本、请求 Provider、广告、签名哈希、结果回收与消费者必须成套迁移。

#### 4.1.2 从已打开的文档创建环境

- 入口：三维工作区的文档菜单提供“从此文档创建仿真环境”。点击时捕获明确的文档会话身份，而非后台执行时重新取 ActiveDocument。
- 已绑定且有权限：进入现有环境，不再新建。无权访问的绑定只返回不可用，不泄露所属环境信息；并发创建由服务端文档会话唯一约束裁决。
- 未绑定：在 Simulation 域创建一个私有环境与同文档的绑定，初始化状态为 `importing`。不调用 OpenDocument、InsertDocument、关闭文档或重新加载，不导出 PLMXML，不加载几何。
- 自动收集当前文档中的全部模型插入实例（在线与本地分别记录）、AH 虚拟节点、顺序及产品复制链接。不得把 CPS 产品结构转换成可编辑 AH，也不得将显示/隐藏状态误当作模型存在性。
- 读取按固定观察代次分片落入暂存区，部分结果可浏览但不作为删除基线；同一 AH 完整且引用解析成功后才可建立合并基线。CPS 不完整的相关引用保留待解析状态，不丢弃。
- 创建完成和结构同步完成分开显示。断线/取消保留环境和已接收数据，可继续；不因失败关闭原文档，也不反向删除原文档结构。
- 创建中切换文档不会把后续数据写进新文档对应环境；任务继续绑定原文档，原文档关闭则暂停。UI 的晚到响应不能抢回用户选择。
- 首次发现的模型显示“首次发现：时间”；后续有可信真实插入时间时补充来源，不伪造历史。
- 验收包含：同名重复实例、在线/本地混合、未加载几何、空文档、局部 E_PENDING、重复点击、并发创建、跨环境切换、关闭重连和十万节点分页。

### 4.2 来源策略

**在线来源**：直接使用在线产品结构；缓存是加速手段，不替换来源身份。默认恢复上次明确接受的修订/配置；若源系统不能重建该配置，报告不可精确恢复，并由用户选择接受当前来源或使用已有显式快照，禁止静默升级。

**本地来源**：链接需要验证权限、存在性、依赖闭包和内容指纹。文件内容变更要形成新来源观测并提示更新。仅链接的环境标明设备约束；文件丢失不能显示可恢复。原有本地 PLMXML 来源继续有效，不按名称自动迁成在线来源。

**在线新增模型**：在绑定文档中插入新在线模型，先发现新来源并提示关联；其 AH 引用可以暂存为 unresolved，但不能宣称可恢复。另开独立在线文档仅进入文档列表，不自动纳入当前环境。

### 4.3 首次进入、恢复

1. 读取环境权限、来源定义和已保存 AH 状态。
2. 查找并验证当前 Connector 内的有效文档绑定。
3. 命中则复用；未命中则按在线来源或本地来源打开/组合专属文档，绝不接管任意 ActiveDocument。
4. 直接读取 CPS，逐步建立稳定身份到运行 key 的映射。缓存可先显示，但未验证映射不能用于写入。
5. 原生创建 AH 并添加引用；模型来源依赖未满足的条目进入待解析状态。
6. 确认文档激活及三维窗口挂接后提交 UI 切换。结构同步可继续进行，UI 明确显示进度。

空 AH 必须可恢复；不可因 PLMXML 导出省略而丢失。模型打开/恢复和 AH 重建允许首入执行一次；AH 日常修改不得重新打开整份文档。

### 4.4 双向文档选择交互

三维工作区页头的“切换文档”入口与右下角文档名打开同一个选择器；不拦截模型区普通点击、旋转或选择动作。列表按文档显示名称、对应环境、在线/本地来源提示、当前活动状态；大量条目分页/虚拟化并支持搜索。

| 触发 | 必须结果 |
| --- | --- |
| AI00 选择已绑定文档 | 激活并嵌入该文档，同时选中其环境 |
| AI00 选择未绑定文档 | 展示文档，环境明确为“未绑定环境”，清除旧环境操作上下文，不自动绑定 |
| AI00 选择环境 | 复用其存活文档；不存在则打开/恢复 |
| VisMockup 自身切换文档 | 检测后走同一个切换协调流程；按绑定选环境或显示未绑定 |
| 无权限访问已绑定环境 | 不读取其业务数据、不自动解绑；显示不可访问状态并禁用环境写操作 |
| 文档关闭 | 失效该 session 的 key 和窗口绑定，不误选另一文档作为替代 |

切换请求使用递增 generation，最后一次意图胜出；迟到结果只能记录到原请求，不能改变当前环境或画面。程序触发激活引起的通知按 generation/document identity 去重，防止循环。

切换阶段为 requested → activating/opening → attaching → committed，失败进入 failed。切换期间屏蔽环境写控件；如果 VisMockup 已换文档而挂接失败，隐藏旧画面并提示，不伪装仍保持旧一致状态。

切换不默认关闭旧文档；旧文档剩余批次安全暂停或按原文档范围完成当前小片。人工修改尚未回收不因切换丢弃。内存淘汰暂不默认启用。

### 4.5 在线结构读取与完整性

读取使用原生 CPS 接口，不遍历可见 UI 行数作为模型全量。不以“显示所有数模”触发几何加载。若需显式展开/补取结构，先验证该入口不加载全部几何，再接入。

枚举使用迭代队列，max_nodes、max_depth、截止时间和分页游标明确；同时核验父子关系、重复身份、叶标志及驻留错误。单个巨大父节点的孩子列表也分片，避免内层循环绕过预算。

完整性分类：collecting / complete / partial / stale / failed。complete 要求没有未处理队列、截断、未解决结构错误，且文档代次和观测一致性检查通过。根内部无名称可单独分类；业务节点 E_PENDING 不能忽略。

跨多片读取没有天然原子快照。优先通过原生变化序列/通知验证；接口不足时读后做结构复核。若期间变更且不能确认一致切面，标记 stale/partial，不产生删除判定。两遍相同不能保证 Teamcenter 服务端已经是最新状态。

### 4.6 时间与历史比较

每次结构观测保存 observation_gid、采集起止 UTC、来源对象/配置、可获取的服务端修订/时间、结构指纹、完整性、缺口清单及会话信息。服务端时间未知保存 null 与 unknown，禁止用采集时间补造。

完整结构内容未变可复用内容制品，但每次采集保留独立观测记录。历史观测不可被新观测覆盖。变化比较以稳定实例身份为基础，区分新增、删除、父关系变化、属性变化及无法判定；运行时 key 不进入跨会话语义指纹。

来源更新只生成变化候选，用户接受前不升级环境的已接受来源配置。结构历史支持比较，不代表可以重建历史几何；需要历史几何时使用来源系统可重开的修订或用户显式保留的快照。

### 4.7 AH 双向增量同步

以 B=最后一致基线、A=AI00 当前状态、V=原生 AH 当前完整观测进行三方比较：

- 仅 A 改变：生成原生差异。
- 仅 V 改变：通过受控 Simulation 写能力回收。
- 双方相同改变：合并确认，不重复执行。
- 不同节点独立变更：仅在合并后父子关系合法时合并。
- 同节点不同修改、删父与改后代、合并造成环、身份歧义：冲突，保留两侧，不最后写入覆盖。

第一期采用保守节点级冲突，不将同节点不同字段变化自动拆开合并。冲突解决必须对精确 A/V/基线版本授权；版本已变化则要求重读。

只操作明确绑定的 AH 集合。首次建立绑定时捕获选择范围；文档中其他无关 AH 不因全局枚举被自动接管。发现新的手工 AH 时提供“纳入当前环境”选择；已纳入 AH 内的新节点自动回收。

CPS 部分读取不能证明 AH 删除；AH 部分读取同样不能证明节点删除。第一期缺少完整基线/完整 AH 观测时不自动执行删除。CPS 引用解析失败的节点保留 unresolved，不移除用户关联。

持久化 AI00 变更及待执行意图后，再执行原生修改；成功读回才推进 applied_revision。业务库与桌面无分布式事务，必须区分 saved_revision、applied_revision、observed_revision。状态不可只用一个“已同步”。

来源模型原始树始终只读；移除 AH 产品引用不自动卸载源模型。模型更换和在线来源刷新是独立显式流程，不夹在 AH 差异处理中。

### 4.8 万级批量性能与不中断交互

完整调度、分页、背压、冷调用降级、租约和性能验收规则见专项规格。以下是摘要，不替代专项中的进程级串行与不可抢占限制。

- 输入按 BOP 一次创建/修改的批次归并，服务端批量写和分页提供差异，不每节点调用一次全量读/保存。
- 目标状态按稳定节点身份合并；未执行的反复改名/移动保留最终意图，新增后删除可抵消。已执行或 outcome_unknown 的动作先核验再归并。
- 每份文档串行写入，先父后子创建、先子后父删除；有未满足依赖的引用延后，不丢弃。
- 原生 UI 线程以短片执行，初始调优目标 10ms，并设调用数和子列表项数上限；片间让出消息循环。单次原生调用不能被强行抢占，超长调用单独记录并采用结构就绪检查、降级或暂停，不能承诺固定响应上限。
- 合并计算、序列化和网络/磁盘工作离开 VisMockup UI 线程；不得从任意线程调用线程亲和原生对象。
- 游标持久化绑定 plan_hash、环境版本、document session；崩溃后对 uncertain 操作读回，不能盲重放。换 session 后重新解析身份和计算差异，不能沿用原 key 游标。
- 当前环境优先，后台文档不无限并行；回收通知合并，定期差异核验补漏。程序写入回声根据预期变化确认，不粗暴忽略整个时间窗口的手工修改。
- UI 显示已完成/待处理/失败及正在补取结构；未知总量显示“已发现 N”，不伪造百分比。

容量验收分别覆盖“1 份 AH × 100,000 节点”“10,000 份 AH × 10 节点”“单父 100,000 孩子”和“100,000 实例在线 CPS”；不得未经用户允许把很多 AH 合成一份。

### 4.9 持续保存、关闭与恢复

日常持续保存模型来源定义、AH、产品引用、结构观测和同步基线，而不是仅在退出时保存。正常关闭前尝试排空回收/持久化队列；失败明确提供重试或带未保存风险关闭，不宣称保存成功。

异常退出后恢复到最后已确认持久化版本，未确认区间明确标记。不能承诺进程被强杀后从未读出的手工修改可恢复。

跨会话重新打开在线来源或本地链接，重建 CPS 映射并恢复 AH。未支持的手工变换等只保证正常切换时留在原文档内，不保证重开恢复，UI 必须提示范围。

### 4.10 UI 状态与错误

分别呈现：选中环境、活动文档、来源状态、窗口内嵌状态、结构完整性、保存/应用版本和冲突。禁止“已内嵌”推导“已同步”。

错误合同至少区分：文档消失、会话代次变化、绑定歧义、来源不可访问、结构 partial、实例匹配歧义、版本冲突、执行结果未知、原生版本不支持。具体公开错误码在合同评审时确定，不将本节文字当作已注册契约。

## 5. 验证与交付顺序

1. **直接读模型**：生产化文档发现、CPS 读取、partial 状态和时间观测。先解决读取链路，不延续 PLMXML 兜底掩盖。
2. **双向切换**：环境↔文档绑定、选择器、原生活动切换、未绑定状态、失败一致性；不以全量同步完成作为切换前提。
3. **增量写与回收**：验证尚缺的 AH 子节点操作，接入幂等意图、读回及三方冲突，范围仅 AH/引用。
4. **关闭恢复与规模验收**：在线身份重开、本地失效、历史观测、崩溃、10,000 节点/10,000 AH。

验收必测：A→B→A、同名不同文档、未绑定文档、权限不足、快速切换迟到回包、原生文档关闭/重启、部分读取不得产生删除、线上更新不得静默升级、重复回收、程序写回声、删除父节点与手工后代冲突、取消/恢复不重复、几何可见性不被结构读取修改。

每项分开记录单元测试、协议/Provider 测试、真实 VisMockup 运行证据。性能记录节点/边/AH 数量、冷/热状态、耗时、原生调用时长分布、UI 响应与取消延迟；不以单次 0.129 秒结果作为保证。

当前证据：既有 AH Capability 与物化基线测试 11 passed；尚未完成的新合并模块测试曾因模块不存在失败，不能视为已有实现；本规格没有运行新功能端到端测试。

## 7. 未验证风险与发布条件

- 在线来源完整身份、修订规则和历史配置重开能力尚未验证；不明确则不得标记可精确恢复。
- 原生文档发现不能依赖当前探针地址或存在某个测试 AH；无 AH 文档也必须能读取 CPS。
- group 创建/移动/删除、跨文档激活通知及模型增量插入需真实验证；缺项阻止相应功能发布，不回退为静默重载。
- 一个未驻留节点的根因未知；提供局部重试和诊断，不以加载全部几何绕过。
- 在线数据变化和长遍历的非原子性需明确反映在观测完整性中。
- 当前多个 test 工作树存在其他任务改动；只修改对应 owner 路径，保留无关内容。

用户复核本更改规格后，旧实施计划需按上述顺序更新，再进行正式实现与逐项验收。
