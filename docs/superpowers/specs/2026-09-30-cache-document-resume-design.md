# 固定缓存原生文档切环境恢复设计

状态：用户已确认设计，待实施计划审阅。承接 `docs/verification/2026-09-30-tc-local-open-execution.md` 中切回环境后窗口已恢复、已加载装置仍为问号的未完成项。本设计先处理同一页面会话内切换环境再切回；Connector 重启、性能及双物理客户端验收单独跟踪。

## 目标和约束

切回已有 VisMockup 文档的环境时，已加载节点只有在当前身份、固定来源和原生会话重新核对后才恢复控制关联；显隐状态必须来自原生回读。未加载、无法定位或无法核对的节点继续显示问号。恢复不得新建模型打开计划、下载 JT、插入实例、改变坐标或显隐，也不得以无范围参数的整文档打开绕过问题。

共用缓存仍只保存固定 TC 元数据、文件引用和装配依据；运行时映射、JT 文件与显隐只属于当前客户端。保留 10 文档限制、授权、单环境单文档/单根及未知效果不自动重试。

## 原因与方案

`live_document_bootstrap.js` 切环境时关闭本地交互；`cad_sim.js` 删除 `_cacheViewer` 并把显隐置为未知；`_refreshModelDocuments` 再替换文档对象。切回只核对并显示原生窗口，未恢复缓存控制关联。旧 `cache_source.live_document.bind` 依赖原打开回执的新鲜度与当前 Connector 运行代，不能当作长期恢复凭据。现有 `actOnProductNode` 校准入口会先确保缓存打开，还可能在大树中漏掉前 2000 个树节点以外的已加载节点。

采用独立缓存文档恢复契约：新鲜签名原生身份 + 原绑定 + 固定缓存来源共同核对，向当前运行代签发新控制授权；只针对先前已加载范围回读。单纯保留 `_cacheViewer` 会信任过期映射，自动重放子树打开可能重复未知原生效果，均不采用。13 项相关前端基线测试通过，但不覆盖此恢复场景。

## 证据与接口

前端只在精确范围打开且绑定成功后，按 workspace/document 保存内存候选：固定 `cache_binding`、最新 `package_hash`、原生 `document_session`、已加载的结构字段、合并后的 `node_map`、排除原因及加载范围。先前各范围只有在同一文档会话和固定批次下完成才可合并；结构候选不保留节点的旧 `visible`/`visibility_state`。候选没有 JT 路径、凭据或预期显隐，不进入服务端结构缓存、localStorage 或模型文档 JSON，页面退出即消失。切走时 UI 和本地授权立即失效；未完成打开、未知效果不得新增候选；未知效果发生时隔离旧候选。

沿用受管理窗口选择及前后两次身份检查。新 `simulation.environment.cache_source.live_document.resume@1` 输入为 workspace/document、当前签名 `identity_operation_id`、预期文档会话、预期工作区版本、会话 nonce 与幂等键。后端在事务中核对租户/用户/设备/当前 Connector 运行代、唯一有效环境绑定、原生会话，以及文档 `teamcenter_cache_snapshot` 类型；固定 `cache_binding`、保存的 `package_hash`/`content_sha256` 必须与活跃来源关联 revision 一致。任何来源、版本、设备或会话冲突都拒绝；幂等请求不可借用另一 nonce 的授权。成功时只续接当前运行代的来源关联并签发该 nonce 的交互 grant；不新建打开计划，不改缓存来源或原生文档。现有在线恢复契约不改变含义。

Electron Main 增加独立 `resumeFromCache` 入口，沿用受信发送者、闭合输入、grant 安装、`prepare_document` 及 attach 前后身份检查；只接收新恢复契约授权，不走 `openSource` 或旧 `openFromCache` 的 launch 回执路径。返回新 `visibility_context`、会话和文档号；渲染进程不能自造 grant。当前 owner/slot 有未知效果时拒绝恢复。

## 页面恢复流程

1. 切走时立即撤销控制并清空可见状态，取消在途打开；只保留已成功的内存候选。异步步骤均检查环境选择代数。
2. 切回后读取权威工作区/文档及固定批次身份，核对原生窗口和后端绑定；候选的 workspace、document、`cache_binding`、`package_hash`、原生会话完全一致且没有未知效果，才请求恢复授权。
3. Main 安装 grant 并再次检查同一原生窗口。页面将候选结构/映射附着到当前刷新后的文档对象，`_cacheViewer` 仍非持久化；映射冲突或对象再次替换时撤销控制。
4. 新的只读校准仅遍历候选中已加载且可定位的节点，按现有 `readVisibility` 限额分批回读；不调用 `ensureCachedReady`、`cache_source.open.request` 或任何显隐写。每批核对 `visibility_context`、选择代数和树版本。mixed、排除、未映射及失败维持 mixed/未知，不从旧布尔值推断。
5. 全部核对和回读完成后刷新树控件。页面重载无候选、会话/来源变化、超时、授权失败、未知效果或迟到结果时，原生窗口可继续显示，但不恢复旧控件；节点保持问号并提示显式处理。

## 验证和证据

测试先失败再实现：多个已加载装置切回只回读不打开；16k 级结构后部的已加载节点不被 2000 上限漏掉，未加载兄弟维持问号；会话、批次、设备、运行代、版本、来源关联、未知效果和迟到结果冲突均拒绝旧控件；重复恢复幂等、不增加原生实例。分别覆盖后端事务/授权、Main 入口和页面集成，并运行相邻回归。

日志区分“窗口已恢复”和“控制及显隐已校准”，记录身份/来源核对、grant、映射、回读及拒绝原因，关联 workspace/document、设备、会话摘要、批次与已加载/未知数量，不记录 JT 路径或凭据。

真实单机验收须先等后端就绪并正常登录，再核对切换前后原生会话、文档/根/实例数、已加载实例世界矩阵及显隐，并证明没有新的缓存打开、JT 下载或显隐写。旧运行代的签名身份必须拒绝；若重启后取得当前运行代的新鲜身份且原会话不变，恢复契约可以续接关联，但不据此宣称 Connector 重启保留文档路径已验证。没有实机证据只报告自动化结果。温缓存耗时、首次文档数量不可验证和双物理客户端也各自保持未验证/未解决。
