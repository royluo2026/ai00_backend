# 数模缓存与仿真：准备数据与 JT 下载分离

状态：按用户 2026-09-30 最新要求重新规划，尚未实施。本文替代此前将 JT 上传 OIS、以云端 artifact_ref 准备可打开批次的方案。

## 目标与边界

- JT 本体存放在 TC 文件存储，通过 FMS 下载到使用者本机；此流程没有上传 JT 到 OIS 的动作。
- 数模缓存提前准备结构、属性、准确文件标识、实例坐标、装配描述与节点依赖索引，不下载 JT 本体。
- 仿真点击只做所选范围解析、权限和会话检查、本地缓存检查、缺失 JT 下载、本地打开和状态同步。
- 下载凭据具有时效性，只在需要传输时获取，不写入共用缓存、装配包或日志。
- 不以“已缓存结构”或“引用准备完成”宣称 JT 已下载、可以离线打开或文件内容已经验证。
- 历史批次仍使用其原始树、版本和坐标。文件缺失、版本依据冲突时明确报错，不替换成最新 TC 树。
- 缺坐标节点按已确认策略排除几何、保留问号及原因；其余有效部分可加载。
- 保留直接从 TC 加载的独立入口。

## 共用数据与客户端数据的边界

数模缓存是系统共用的数据源，不属于创建批次者的个人仿真环境。所有具备现有项目/租户访问权限的使用者消费同一份固定批次和准备产物，不能按 actor_gid 重做一份缓存。这里的“共用”不取消既有权限隔离。

| 数据 | 归属 | 其他客户端是否随之改变 |
| --- | --- | --- |
| 固定树、属性、坐标、TC 文件引用、基础装配描述、排除原因 | 服务端共用批次 | 读取同一版本 |
| 下载任务、进度、错误、取消状态 | 发起任务的客户端/设备会话 | 否 |
| JT 实体、实际内容 hash、本地路径、缓存容量与清理记录 | 下载它的本机 | 否 |
| 当前环境的原生窗口、加载状态和显隐回读 | 对应客户端与当前文档 | 否 |

同一账号在 A、B 两台电脑也是两个本地下载状态。A 下载完成后，B 必须检查自己的磁盘，缺失则自行从 TC/FMS 下载；不能用 A 的成功回执证明 B 有文件。客户端重启后检查真实本地文件，不能从服务端历史任务直接恢复“本机已下载”。A 清理本地文件不改变共用批次、不清理 B 的文件。

服务端可记录带 device_id/runtime/session 的任务审计，但不得把某台电脑的“已下载”写成共用批次的就绪条件。共用状态只表示装配依据的准备程度；本机状态表示本机实际下载和加载程度。新本地接口只回报摘要，不将本地路径作为可跨客户端消费的资源。

## 阶段与产物

| 阶段 | 所属模块 | 工作 | JT 字节传输 |
| --- | --- | --- | --- |
| 采集快照 | 数模缓存 | 固定树、属性、实例关系、坐标、dataset_uid/file_uid 和可读取的文件版本依据 | 无 |
| 准备装配 | 数模缓存 | 验证坐标和引用、生成相对路径装配描述、建立节点→实例→文件依赖索引、列出不可用原因 | 无 |
| 解析选择 | 数模仿真后端 | 授权固定批次，按所选节点取子树和依赖，生成绑定当前环境的签名任务 | 无 |
| 检查本地 | Connector | 查找受控本地缓存、验证实际文件和记录；区分已加载与仅在磁盘上存在 | 无 |
| 下载缺失文件 | Connector + TC/FMS | 获取有效下载凭据、读取必要的文件元数据、下载所选范围缺失 JT、校验并原子落盘 | 仅 TC/FMS → 本机 |
| 打开与显隐 | Connector + VisMockup | 本地路径适配、插入当前环境、核对实例与坐标、批量显隐、回读树状态 | 无 JT 网络传输 |

装配描述主体可提前生成；环境名称、组合后的单根文档、所选范围和本机路径必须运行时适配。这是有界的本地/元数据工作，不得混入 FMS 遍历、JT 上传或整树重采集。

## 数模缓存模块

固定快照之外增加可重建的准备产物，不更改原快照 hash。产物绑定 batch_id、generation、snapshot_hash、准备算法版本，并保存：

1. 结构和每个 occurrence 的稳定标识、父子关系、已验证变换及单位。
2. 去重文件表：TC endpoint、dataset_uid、file_uid、文件名、relation_type；可取得时记录大小和修改/版本依据，缺失值保持明确未知。
3. 节点到后代 occurrence/文件的索引，避免点击时再查询全部 TC 属性；重复 JT 只下载一次，各实例坐标独立保存。
4. 使用稳定依赖键和相对路径的基础 PLMXML/装配描述，以及可定位到节点的排除原因。

用户界面分别呈现“结构采集中”“装配准备中”“装配依据就绪（JT 按需下载）”“部分可用”“准备失败”。新批次采集结束后自动准备；旧批次提供“准备装配数据”，仅依据已有快照计算，不读取 JT 本体。如果旧快照缺必要字段，列明缺项；需要从 TC 补采时不能悄悄覆盖旧批次。

共用的是项目授权范围内的元数据和装配产物，不是某个操作者的文件上传记录。准备阶段不能依赖仿真窗口，也不能调用 FMS getFiles 或 JT 上传接口。

## 数模仿真与 Connector

现有 vismockup.model.open@2 要求 artifact_ref 和 JT artifact dependencies，不能通过伪造 artifact_ref 或传任意本地路径来绕过。新增版本化的 TC 缓存打开契约（计划使用 vismockup.model.open@3；实现前核实版本未被占用），包含固定批次、环境/文档身份、选择范围、准备产物 hash 和 TC 文件依赖；服务端验证全部文件属于所选快照。

Connector 验证签名任务后，复用既有 TC 登录、FMS 和本地文件校验能力，将依赖解析为受控本地文件，再调用现有单环境文档装配和批量显隐机制。下载在工作线程执行，COM 操作仍在 STA 上，避免阻塞页面与交互。取消下载可以保留已校验的文件；取消后的旧任务不能继续插入环境。

新结果回执记录固定批次/准备产物 hash、实际文件 hash/大小和原生文档身份，不向服务端暴露本地绝对路径、凭据，也不要求上传文件本体。相应更新打开证据校验、live_document 绑定、恢复和日志分类，不能只改前端入口。

本地缓存按 TC 来源、文件身份及可用版本依据建立索引；内容 hash 在实际下载后计算。复用前校验本地记录和文件，来源或版本冲突不共用。无预期内容 hash 的历史快照，只能证明选取了其记录的 TC 文件身份，不能虚构“字节与快照时刻完全一致”的保证；如 TC 提供可验证的版本依据则核对，不符时报错。

本地缓存有容量与过期清理策略，沿用已有可用配置；没有现成配置时实施阶段明确默认值并测试。已打开文档可能延迟读取 JT，关联文件必须保持引用保护，关文档后才可清理。缓存清理不删共用快照；下次显示自动从 FMS 补下载。

## 日志与验收

日志分开记录 scope_resolved、local_cache_checked、fms_preflight、jt_download_started/progress/completed、local_file_verified、assembly_bound、native_open、visibility_batch、tree_state_readback。每条关联 workspace/document/batch/node/operation/capability；显示文件数量、字节、缓存命中、耗时和当前阶段。未知字节数不得显示虚假的百分比；不得包含凭据。

硬性验收：

- 缓存/准备阶段 JT 下载次数=0，JT 上传次数=0。
- 仿真首次打开缺失文件时只从 TC/FMS 下载，JT 上传次数=0，OIS JT 下载次数=0。
- 未点击范围没有 JT 下载，重复文件去重；父节点和零件范围都正确。
- 已加载父节点隐藏/显示不触发 JT 下载，批次调用显隐。
- 本地缓存删除后的重新打开可补下载；打开中关联文件不会被清理。
- 同一环境只有一个文档和一个根，连续加载不同装置保留先前显隐与坐标，紧固件实例不合并。
- 缺坐标保留问号和原因；树最终状态来自原生回读。
- 权限、登录、下载失败、取消、进程重启均有准确阶段日志；不得回退到 JT 上传路径。
- 双客户端：A、B 使用同一批次，A 下载/取消/清理均不改变 B 的本地状态；B 无需依赖 A 在线或 A 的上传记录，自己下载自己缺少的 JT。

性能验收先记录阶段耗时再比较：选择此前未在 AI00 打开的装置，注明 FCC 是否命中。文件大小和网络速度不固定，不承诺任意装置固定秒数；重点消除点击时整树采集、串行云端往返、逐文件任务轮询和不必要的重复 FMS 初始化。
