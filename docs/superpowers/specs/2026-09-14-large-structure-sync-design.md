# 大规模产品结构与备选层次双向同步专项规格

版本 0.1；2026-09-14；状态：设计待复核，未实施性能验收。

本文件是《2026-09-14-online-vismockup-environment-sync-design.md》的规范性补充。发生歧义时，本文件负责规模、调度和恢复细节；主规格负责业务范围、来源与交互。仅适用于 test 实施，不授权生产部署。

## 1. 目标、边界与不能作出的承诺

支持以下独立负载及其组合：

- BOP 导入一次产生 10,000 份 AH，每份含少量节点。
- 单份 AH 包含 100,000 个节点/引用，包括一个父节点有 100,000 个直接子项。
- 在线 CPS 包含 100,000 个实例，分支按需取数、深层结构、重复零件实例并存。
- AI00 编辑、VisMockup 手工编辑、环境切换同时发生。

不修改 CPS；不为读结构调用显示全部、LoadParts 或未经验证的几何驻留操作。产品树是读取/比对来源，只有已绑定 AH 及产品引用双向写。结构时间观测并不承诺保存历史几何。

不能通过把很多 AH 合并成一份、截断树、默默忽略手工修改来通过性能验收。10ms 调度片不能抢占同步原生调用；“AI00 壳窗口可响应”与“VisMockup 模型可旋转”分别测量，不互相替代。

## 2. 三条链路与执行位置

| 链路 | 输入 | 输出 | 原生执行范围 |
| --- | --- | --- | --- |
| CPS 采集 | 文档身份、来源代次、读取游标 | 带完整性的结构观测与实例映射 | 结构只读/已验证结构补取 |
| AI00→AH | 已持久化期望版本、最后一致基线 | 原生差异、逐片读回确认 | AH 与引用写入 |
| AH→AI00 | 绑定 AH 的变化线索与有效观测 | 手工变更、冲突、持久化新版本 | AH 只读，业务写走 Simulation |

三条链路共享同一进程级原生串行执行器，按文档保留队列；不能因为文档不同就并发进入同一个 VisMockup UI 线程。解析、哈希、三方合并、压缩、数据库和网络 IO 在宿主工作线程/服务端执行。只有必要的原生调用及小块数据复制进入 UI 线程。

没有进程内异步结构请求接口时，不得把线程亲和 COM 指针挪到线程池以伪造异步。后台 Broker 只隔离 AI00 等待，不自动解决 VisMockup 被同步调用占用的问题。

## 3. 身份、批次、游标与状态合同

### 3.1 每项工作携带的范围

`tenant + actor + workspace_gid + device_id + process_epoch + document_session + source_generation + binding_revision`。

另携带 `run_id、plan_hash、operation_id、idempotency_key、expected_revision、request_generation`。这些是拟定内部字段，不代表已注册的公共 Capability schema。

运行时 key 只存在于同一 document_session 映射中。跨会话恢复重新解析稳定实例身份；不能用同名、同零件号或旧 key 自动替代实例身份。

### 3.2 批次及操作状态

操作状态：pending → dispatched → observed_applied → acknowledged；也可进入 blocked、conflict、outcome_unknown 或 superseded。

- dispatched 在外部副作用前持久化；不能仅记在内存。
- observed_applied 要有读回证据，不是原生 HRESULT 成功就算。
- acknowledged 要有服务端接受的版本/幂等结果。
- outcome_unknown 禁止直接再次创建/删除，先重读目标。
- superseded 仅用于尚未派发的被后续目标替代的动作；保留审计关联。

每份 AH 保存已确认基线和应用版本；环境级“全部同步”仅在目标版本所有绑定 AH 均确认后成立。不同 AH 部分完成时报告向量/汇总进度，不把最高版本当作整体已完成。

### 3.3 分页与一致性

分页游标必须绑定固定 revision/observation/run、作用域、排序键和到期时间。禁止对正在变化的数据用裸 offset 翻页并认定完整。若不能提供不可变读版本，页间变更使观测失效，重新取得一致基线。

单次流式观测只在 manifest 完成后供删除判定使用。manifest 包含页数、节点/边数量、各块哈希、根集合、缺口、开始结束时间和范围版本。重复页幂等，丢页/乱序/哈希不符不得提交 complete。

## 4. 大规模 CPS 读取

### 4.1 冷读取与热读取

首次读取按已知结构优先显示，后台分批取得未读分支。状态显示“已发现 N、仍在发现”，总量未知不显示虚假百分比。热缓存必须绑定 document_session/source_generation；来源变更立即使相应映射待校验。

队列单元为“父节点 + 子项游标/页”，不是整棵子树。一次 GetNumChildren 后按受控页枚举；100,000 个直接孩子也必须在页边界让出，不允许内层循环无限运行。

遍历不递归；显式栈/队列支持深度上限并报告截断。结构上界默认 1,000,000 节点、2,000,000 边、深度 1,024；超过上界暂停并显示原因，不伪装完整。调整上界通过受控配置和内存评估，不自动无限提高。

### 4.2 完整性与异常节点

逐项保存查询状态；E_PENDING、驻留失败、超时、不可访问、子项索引失败各自记录。已知内部包装根无名称单独分类，不污染业务节点名称。

只有子枚举成功且叶语义一致，才能确认分支闭合。没有子项但叶标志不确定，仍是缺口。正在补取、达到预算、文档切换或网络断开都产生 partial，不产生删除。

第一期删除要求目标 AH 范围有完整、同代次的一致基线与当前观测。CPS 的未解析引用保留，不因缺失自动删 AH。未来若做局部分支删除证明，必须新增独立覆盖证明合同；本期不以局部成功放宽保护。

### 4.3 冷调用阻塞的明确降级

在真实环境先测每个结构入口是否同步访问 Teamcenter及耗时分布。若存在已验证的“只补结构”的异步请求/完成通知，使用单请求在途与增量完成回调。不能凭名称推断 EnsureResidence 不加载几何。

若只有可能长时间阻塞的同步调用：

1. 不在旋转/拖动等交互活跃期间启动新的未知成本冷调用；交互繁忙可暂缓冷补取，但继续显示已读结果。
2. 冷补取显示“可能短暂占用 VisMockup”；无法保证模型交互延迟时，该路径不通过“全程流畅”验收，不能用壳窗口响应掩盖。
3. 独立 watchdog 标记超时/请求取消；只阻止下一次调用，不能强杀 UI 线程或释放仍在调用中的 COM 对象。
4. 调用未返回时保留原文档身份、禁止冲突性原生切换；AI00 可显示切换请求等待中。用户若要终止进程，必须另行确认，不能自动强杀。
5. 冷模式长期阻塞时保留 partial 与读取游标，允许用户暂停/继续；不自动退回导出 PLMXML 或显示全部几何。

冷模式当前不保证有安全异步入口，这是探测门槛，不是可以用配置消除的风险。

## 5. BOP 巨量变更到 AH 的差异计划

### 5.1 构建与排序

按 BOP 批次形成不可变期望版本；分块暂存，完整 manifest 校验通过后原子发布版本头。数据库事务限于块写或版本头切换，不在一次超大事务中等待 VisMockup。

稳定 ID 建索引，差异计算目标 O(N+E)，排序至多 O(N log N)；禁止逐节点全表查询和递归重建整个树。复用未变块/分支指纹，但指纹命中必须处于同一身份与完整性合同。

按 AH 划分计划；节点创建父先子后，删除子先父后。移动先验证最终图合法，再生成安全顺序；若移动依赖环或不能证明中间态合法，生成冲突/待处理，不临时修改 CPS 或私建未声明中转树。

模型引用创建依赖来源与目标 AH 节点就绪；引用未解析只阻塞其依赖子图，其他独立 AH 可继续。删除父节点和修改其后代归为同一冲突域。

### 5.2 合并与背压

待派发相同节点连续改名/移动归并成最终意图；新增后删除可抵消。不得合并越过已派发动作、用户确认边界、来源版本或 session 边界。排序操作不与引用身份混为同一字段。

队列采用持久化计划与有界内存窗口：默认每原生进程最多驻留 2,000 条待执行操作或 8 MiB（先到者为准），其余在受控存储；不把 100,000 项一次性塞入 IPC。

高水位 80% 停止预取，低水位 40% 恢复。磁盘不足、存储写失败或配额超限立即暂停接收新执行任务并明确报告；AI00 可以继续已获授权的服务端编辑，但不得假称已派发/本机已保存。

批量计划尚未派发部分可被更新的期望版本取代；原有审计与操作 ID 保留关联。不能为压缩队列静默丢弃已经接受但尚未持久化的意图。

## 6. 调度、取消与文档切换

### 6.1 初始受控参数

下列数值是待测的初始配置及保护上限，不是已测得性能：

| 参数 | 初值/规则 |
| --- | --- |
| 原生热执行片 | 目标 10ms；最多 32 次原生调用，先到者让出 |
| 子列表读取页 | 最多 256 项；原生页调用仍计入时间/调用预算 |
| 原生数据返回块 | 最多 256 KiB；过长字段拒绝或独立制品，不静默截断 |
| 服务端观测/差异页 | 最多 1,000 项且 1 MiB，先到者截页；能力现有更小预算优先 |
| 每进程原生并发 | 1；CPS 读取与 AH 读写共同遵守 |
| UI 进度通知 | 最多 4 次/秒，终态/错误立即通知 |
| 回收变化合并 | 200ms 安静窗口；持续变化最长 1s 发起有界读批次，不等无限静默 |
| 原生慢调用警戒 | 100ms 记录；1s 标记慢；5s 启动等待/取消提示（不强行抢占） |

批次自适应只在这些上界内改变片大小：根据最近原生调用耗时减少/增加调用数，网络冷调用不混入热调用吞吐估计。

### 6.2 优先级与饥饿

优先级依次为会话失效/停止派发、切换/取消控制、活动文档小批编辑与回收、活动文档大计划、后台安全保存与校验。控制消息不需要排在 100,000 条业务动作之后。

默认非活动文档不执行需要激活的原生任务，不偷偷抢焦点。仅当接口明确支持不激活访问时才允许后台安全片；每 10 个普通片至少给一个已等待的合格低优先级任务，避免无限饥饿。没有后台访问支持时明确报告暂停，不能承诺后台同步完成。

### 6.3 切换与取消语义

每次切换增加 request_generation；取消旧意图不撤销已成功副作用。已在途调用返回后仍按旧文档记账和读回，不得归入新环境。

切换可以先展示缓存和等待状态；原生激活与嵌入确认后才提交当前工作上下文。旧画面失效时隐藏，不形成 A 环境+B 模型的无提示状态。

取消大批次停止未派发动作并持久化当前位置，标记 partially_applied；不自动删除已创建节点“回滚”。恢复基于读回重新计算剩余差异。用户要求撤销是独立受权反向变更，不等于取消。

## 7. 手工回收、通知丢失与冲突

### 7.1 变化捕获

优先使用验证过的原生 AH 通知；通知只是“这里可能变了”的线索，不作为唯一事实。合并同 AH 的脏节点集合，读取当前受影响范围。通知无稳定 ID 时，扩大到 AH 范围，不猜测节点。

无通知或通知丢失：活动绑定 AH 进行有界轮转校验，默认 5s 开始一个校验片；大集合轮转完成时间要显示，不能承诺每份 AH 都在 5s 内检查。切换、重新连接和关闭前提高回收优先级，但不触发无限全量扫描。

所有回收先入受控持久化观测队列，再提交服务端。网络失败不覆盖基线。若用户失去权限，不继续上传业务写或重放旧授权；保留/清理缓存遵守现有租约与数据策略。

### 7.2 三方比较与回声

B=最后双方确认的完整状态，A=服务端版本，V=同一绑定范围的有效原生观测。比较以节点为冲突单位，并复核最终图的父子约束；不只比较名称。

程序批次记录预期变更、基线、执行范围与 readback。观察结果与预期一致才确认为自身回声；同一时间发生的额外变化仍进入手工比较，不能用“暂停监听两秒”吞掉它。

计划生成和真正执行之间可能发生手工修改。每个写操作在 UI 线程内紧邻调用前核验目标 AH/节点身份和预期父节点、名称或关系；不匹配即停止该冲突域，重新采集，不先覆盖再回收。若原生调用内部消息重入使检查与写入无法保持一致，必须验证原生事务/版本机制或采用更保守的人工确认路径；不能声称仅三方合并就消除了写入竞态。

冲突保留 A/B/V 及完整性信息，只暂停冲突节点和依赖后代；独立 AH 可以继续。基线仅对双方确认范围推进；冲突未解决时环境整体不显示已同步。

新手工 AH 先列为未纳管候选，不自动吞并其他文档内容。已纳管 AH 内新增引用可回收，但来源稳定身份缺失时保留 unresolved，不假造模型制品或对 CPS 写入。

## 8. 持久化、重启及多客户端

每个环境的活动写执行器使用服务端租约和 fencing_token；新执行器获得更高代次后，旧执行器的确认/写请求拒绝。租约验证在每个派发片前，过期则停止新调用；在途调用不能撤销，标记需重新核验。

片前验证使用已验证的签名授权、单调时间有效期和本机当前 fencing 代次，不每 10ms 发一次网络鉴权；续租与撤销通知在后台进行。撤销传播时限按治理合同声明，不虚称离线即时撤销。原生入口另设进程级唯一执行器/代次校验，服务端 fencing 只能拒绝陈旧提交，不能单独阻止进程内已经在途的调用。

其他 AI00 客户端可以通过现有并发版本规则提交编辑；不能同时驱动同一个文档的第二套原生写队列。VisMockup 手工修改不受该锁禁止，通过三方合并处理。

持久化检查点包含 intent、已确认结果、基线、plan_hash 和 session，不保存可跨进程复用的原生指针。服务端收到结果后丢失响应，重试用同一幂等键获取结果；原生超时后先探测后续状态，不能机械重放。

正常退出先停止新派发，排空已读手工观测并提交；保存失败提示重试或有风险退出。异常退出只恢复已持久化状态，未读出的手工操作可能丢失，必须公开这段风险窗口。

磁盘和内存缓存可淘汰已确认、可重建的块；不可淘汰未确认意图、未上传手工观测和未解决冲突。来源凭证不写入模型 JSON/日志，按既有系统认证取得；文件路径和名称日志遵守脱敏规则。

## 9. 前端规模与历史比较

文档列表、AH 清单和树按稳定 ID 虚拟化；DOM 常驻行目标不超过 300，不把全树 HTML 插入页面。仅展开可见路径；用户“展开全部”不等于加载几何，也不允许一次构建十万 DOM 节点。

后端批量读/写、前端差量 patch，不每个节点 emit 一次完整 workspace。滚动、展开和选择状态与模型内容分离，更新不重置整棵树。离线缓存保持原只读权限语义。

观测 manifest 保存采集区间、来源版本/配置、来源更新时间（未知为 null）、完整性与缺口。服务端和设备时间分别保留，时间偏差不以客户端时钟决定更新胜负；顺序以服务端版本/序列为准。

历史结构按内容块去重，保留独立观测记录；不会每次小修改上传整份十万节点模型。指纹明确算法版本、字段白名单、排序和字符串规范化；来源 namespace/实例路径参与身份，禁止把两个同零件不同位置实例合并。

模型来源升级先形成候选观测，接受后增加 source_generation、失效相关运行映射并重新验证引用。旧观测保留用于比较，不静默绑定到新的相似节点。

## 10. 性能、正确性与故障验收

以下是测试门槛而非已实现承诺；机器规格、网络、模型、插件版本、缓存冷热和采集完整性一并记录。

| 测试 | 可判定验收条件 |
| --- | --- |
| 10,000 AH，每份 10 节点 | 100,000 节点/全部 AH 不丢失，逐项身份/父关系/引用读回一致；不合并业务 AH |
| 单 AH 100,000 节点 | 无递归栈溢出；计划和传输遵守页/内存上限；原生结果与期望一致 |
| 单父 100,000 孩子 | 子枚举/创建可在页边界让出，不能一个内层循环独占执行器 |
| CPS 100,000 实例，含未驻留分支 | 冷/热分别测；结构补取不改可见性或调用几何加载；缺口报告正确 |
| 深度 1,024 / 1,025 | 前者可有界处理；后者显式 partial/上限提示，不崩溃或伪造 complete |
| 持续 60s、每秒 1,000 次同节点目标修改 | 队列合并有界，输入停止后正确收敛；不将中间重复意图逐条无限执行 |
| 100,000 次不同节点修改 | 不以合并掩盖丢失；持久化溢出或配额拒绝可见且可恢复 |
| 高负载下 A/B/A 与原生切换 | 100 轮切换无错文档写入、无过期画面提交，未绑定状态正确 |
| 执行中手工改名/移动/删除 | 自身回声不循环，手工变化不丢失；同节点及删父改后代产生冲突 |
| 缺页、重复页、通知丢失、结构变更 | 不完整不删节点，通知恢复/轮转校验最终发现差异 |
| 崩溃切点 | 派发前、派发后未读回、读回后未确认、服务端已提交丢响应各测；恢复无重复引用 |
| 租约过期、另一设备接管、撤销权限 | 旧代次停止新派发/结果不被错误接受，不能重放旧授权 |
| 离线/磁盘满/原生长阻塞 | 明确暂停与风险状态，无丢弃待保存数据、无自动强杀 |

热模式 UI 测试目标：AI00 输入反馈 p95≤100ms；模型交互响应 p95≤100ms；取消停止新派发 p95≤250ms（无不可抢占在途调用时）；热模式自身任务造成连续无响应不得超过250ms。冷模式逐次报告长调用及最大阻塞；若未达交互门槛，不得以平均值或排除冷样本宣称通过。

吞吐不设未经测量的绝对秒数保证，但必须报告总耗时、节点/秒和每调用成本；10万规模与1万规模比较，扣除明确记录的来源取数时间后，总处理时间增长不超过15倍作为复杂度回归门槛。独立计量 UI、网络、原生、落库，不能只测纯算法。

已绑定、来源热就绪且无积压的单次手工编辑，端到端持久化目标≤2s；通知缺失回退模式报告实际轮转延迟，不冒用该目标。停止输入后，用独立全量校验器验证最终收敛和原 CPS 未被修改。

## 11. 必须先验证的技术门槛与治理

尚未验证：原生 AH 事件覆盖/序列、结构异步补取、安全子列表分页、AH 子节点完整 CRUD、后台不激活读取、在线稳定身份、精确重开配置、原生文档激活事件。不存在的能力不能用伪 Provider 或固定成功回包代替。

在这些门槛通过前，可实现并测试纯差异、计划、存储和调度逻辑，但只能标记局部/模拟证据，不能把整个同步功能声明已完成。若同步冷调用无法满足 UI 指标，必须提交真实测量及降级选择给用户，不静默降低验收标准。

Scope、分页、租约、回收和原生命令全部经治理合同执行；新增消费者/执行位置/副作用须更新 Descriptor 与 Provider 绑定。当前 machine_passed / human_approved / runtime_verified 对整项更改均为 unverified，AI 评审始终 advisory。
