## 必须保持的共同不变量

- I-01：名称、临时编码、路径和原生节点号不能替代业务身份。
- I-02：任一执行结果可定位精确 BOP／需求、模型快照、集合、绑定和策略版本。
- I-03：冻结事实不可原地覆盖；原生临时变化不会自动改写基线或 TC。
- I-04：文件缓存淘汰不删除业务版本；会话重启不重建工程绑定。
- I-05：普通打开不产生 AI00 长期模型副本；长期保留必须有显式保存记录。
- I-06：回填及重试不能重复挂附件或覆盖他人新内容；原始完整 BOP 和既有图片保留。
- I-07：所有写入仍经所属业务域与受治理入口；本地加速不取消权限、版本、幂等和审计边界。
- I-08：原生用户可自由操作；自动化不默默控制另一进程、文档或阶段集合。
- I-09：缩略图可持久缓存，在线原图不作长期缓存；待交付 PNG 是可靠结果而非可随时淘汰缓存。
- I-10：未知、部分、失败、跳过、结果不明和成功分别表达，不用零值或成功掩盖未知。
- I-11：备选树 placement 不等于正式工艺绑定；正式语义关系只有一个权威写入者，数模域的反向索引不是第二份绑定主表。
- I-12：业务版本名称不代替自动技术修订；每个有效工艺内容提交原子产生技术修订，已发布版本不可原地改变。
- I-13：同一精确工艺快照可有多份数模适配方案；执行必须明确方案及版本，不能使用全局“最后一次绑定”。

## 实施前的原生验证门

V1：所装 TC 14.2 的实际变量模式、可用保存规则对象及服务输入。

V2：多进程／多文档精确接入、同文档多个阶段集合及可追溯身份；禁止用默认 COM 实例替代目标。

V3：原生结构／位置／选择事件覆盖，事件丢失的检测和低成本修复。

V4：受支持的 FCC 获取方式、缓存命中证据、分段与整文件就绪、任务中文件可用性及身份映射。

V5：TC 长结构解析的一致性证据和历史文件保留；时间戳本身不能代替快照一致性。

V6：原生操作的界面阻塞、跨文档共享线程影响及批量调用上限。

失败需限定支持范围、保留旧链路或修订规格；不能通过关闭其他实例、下载全部 JT、跳过校核或伪造事件支持来通过验收。

## 不在本次直接实施范围

不重写 TC 规则引擎，不做跨来源相似零件自动确认，不建设无需要的通用事件溯源／消息中间件，不默认全量离线整车，不将演示权限简化带入正式版，不承诺外置即可消除原生线程阻塞。

当前仅落盘指南、改造前源快照及本规格。下一步先评审数据边界与原生验证门，再分子系统编写可执行实施计划；本规格不自动授权生产发布或业务治理审批。
