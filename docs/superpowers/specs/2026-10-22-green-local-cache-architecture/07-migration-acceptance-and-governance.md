# 07 迁移、阶段验收、风险与治理

## 1. 变更分类与状态

跨域架构改造候选，涉及新的场景／快照／基线语义和既有结构、绑定、Connector、附件消费者兼容。当前只新增文档并备份既有源变更，没有实现这些契约。具体能力逐项分类为新增、兼容修改或破坏性版本升级，不能一概沿用旧 contract hash。

- `advisory`: true。
- `machine_passed`: 架构实现 unverified；文档静态检查另记，不代表门禁通过。
- `human_approved`: 用户确认方向与备份操作；正式能力精确 hash 治理审批 unverified。
- `runtime_verified`: 新架构 unverified。

## 2. 已检查与待查的权威上下文

已检查：绿标前后端 test 工作区、当前 Git 提交及源差异、状态栏入口、TC readonly selector／worker、原生嵌入与隐藏路径、安装包规则与缓存组件；备份前选定测试。

待实施前必须检查：真实 Catalog／Registry／Descriptor／Provider 绑定、Capability version GID、相关域表所有权、schema migrations、原子能力消费方、现有流程图与 BOP 的数据权威、标准工序版本对象、附件缩略图服务、可用变更序列和权限撤回策略。未查到不能以设计候选替代真实登记。

## 3. 所有者与契约拆分

craft：BOP 结构／内容、自动技术修订、正式工艺绑定及方案修订、标准映射消费、工艺附件挂接。

simulation：模型快照／集合、场景、绑定草稿／适配工作场景、执行、比较；placement 不代替正式 craft 关系。

digital_model：模型身份与不可变版本、实例端点，以及消费正式绑定的反向查询投影；不产生第二份独立可写绑定主表。跨域传播采用权威事务内可靠发件及幂等投影，读写水位可核对，详见 [08](08-alternate-hierarchy-binding-and-cloud-sync.md)。

knowledge／标准规则所有者：标准工序定义、知识和规则版本、检查契约。

project／baseline 协调所有者：待确认；只协调各域固定引用，不跨域直接 SQL。

desktop Main／Connector：本机投影、存储计量、文档会话、原生调度与可靠输出。

TC/FCC：配置解析和文件缓存外部系统；公开支持边界实测确认。

每个独立可授权、失败、重试、审计的业务效果单独确定契约。规格里不创建虚构 GID；已有查询、工作场景、绑定、截图、附件能力先检查复用。BFF 只读聚合不能承担跨域写。

## 4. 分阶段实施与退出门

### A：原生与数据调查

验证目录入口 V1–V6，梳理流程图和 BOP 真实对象，测当前打开／准备／截图耗时，记录所用数据副本、源版本、设备与原生配置。交付能力矩阵、现有契约清单、数据归属图和性能基线。

退出：能证明同配置结构与打开一致，或明确受限模式；能精确定位目标或明确不支持；事件／文件访问可用性有真实证据。未通过不开始大范围替换。

### B：身份、版本和持久化

只新增兼容对象／字段，旧接口适配；写入保留来源和完整性。测试重复实例、同名规则、日期语义、引用缺失、CAS、跨域准备期间变化。禁止直接把旧名称映射成新确定身份。

### C：流程图与绑定

结构与布局分离，建立标准工序版本接口、未标准化状态，绑定迁移产生待确认集合。测试跨工位移动、同 GBOP 多工序、同零件多实例、布局不触发重绑、无关修改不全线失效。

本阶段还必须交付 [08](08-alternate-hierarchy-binding-and-cloud-sync.md) 的树编排／正式绑定分离、craft 权威提交、digital_model 反向投影和云端同步状态，以及 [09](09-process-auto-revision-and-multi-model-binding.md) 的自动技术修订、发布标签不可变及同工艺多目标方案。现有域结构优先复用，新增契约须独立核实身份／权限和兼容升级。

### D：外置与协同

通过配置开关按设备／工作场景启用外置，停止嵌入行为但保留旧链路回退。测试自由旋转、插入／删除／移动、双文档／双进程、重启、窗口复用、旧 fence、事件丢失及用户接管。

### E：工作集、媒体、FCC 与监控

按 02、03、06 子规格实现；前端首次渲染独立于全量获取，统计后台限频。测试增量丢页／重复页／墓碑、权限变化、原图不长期保留、待交付不误删、FCC 与 AI00 分类分离。缓存切换以受支持获取接口命中证据为准，不以目录存在为准。

### F：自动化闭环

固定计划、本地连续执行、有界交付、craft 条件回填；故障注入覆盖所有持久化边界。不得把 formal reset 改成演示版整线清空。输入依赖改变要冲突而不是盲重试。

### G：基线、比较与灰度

TG0／TG1 冻结与派生、同文档多集合、流程图＋数模联合差异、历史文件不可获取、旧数据来源不足。灰度按工作场景启用；旧任务保持旧契约完成，不能中途改解释。

## 5. 数据迁移与回退

- 先备份和可恢复演练，再在隔离测试副本迁移；不得直接生产试写。
- 新 schema additive；提供迁移版本、幂等标记、原始字段和来源证据。
- 老记录分类：完整可迁移、来源不完整、绑定待确认、原生状态不可恢复。不能统一标完成。
- 已有图片原关系保留，新结果不覆盖旧图；历史附件权限依然有效验证。
- FCC 与现有自管模型目录先只读盘点；不按扩展名批量搬移、删除或宣称已被原生缓存接管。
- 回退关闭新消费者／新写路径，不删除已形成的冻结基线或可靠结果。旧程序读不到新字段时需兼容投影；不能以回滚代码为由破坏性降库。
- 改造前两仓库标签作为源恢复点。运行密钥、数据库备份和用户数据按独立受控机制保管，不进 Git。

## 6. 联合验收矩阵

| 编号 | 故障／输入 | 必须观察到的结果 |
|---|---|---|
| AC01 | TG0/TG1 同件、同名、重复安装 | 集合和实例精确，绑定不串 |
| AC02 | 规则同名但内容改变 | 不错误复用旧快照 |
| AC03 | 用户插入未知来源模型 | AI00 可见，来源待识别，不改基线 |
| AC04 | 原生删除／移动任务相关实例 | 更新差异并暂停／拒绝旧执行 |
| AC05 | 另一端修改 BOP／绑定 | 不覆盖新内容，结果保留可追溯 |
| AC06 | 上传／回填响应丢失 | 幂等确认，无重复附件 |
| AC07 | App、Connector、原生分别重启 | 恢复各自状态，不重复下载／绑定 |
| AC08 | FCC 淘汰／Offline、权限撤回 | 清楚区分不可用、未授权和历史事实 |
| AC09 | 租约过期／两个调度者 | 旧执行者被 fencing 拒绝 |
| AC10 | 流程图离线草稿＋后台更新 | 草稿不丢，云端写回有冲突处理 |
| AC11 | 硬链接／目录重叠／无权限 | 总量不重复，未知不为零 |

## 7. 证据包

每阶段记录代码 commit、真实契约／Provider hash、测试命令与原始结果、测试数据版本、配置快照、设备与原生文档证明、逐段耗时、错误／跳过率、是否模拟及未覆盖项。运行日志脱敏，不记录密码、TC 票据、私钥、签名材料或含 token 的远端 URL。

截图证明 UI／原生效果，不能替代服务端附件关系和版本证据。测试替身通过不等于真实 TC／VisMockup 通过。用户方向确认不等于 super_admin 对精确业务定义的治理审批。

## 8. 当前风险台账

R1 原生 COM 无法指定实例；R2 原生事件不足；R3 TC 配置模式／规则对象差异；R4 长解析一致性不足；R5 FCC 清理与活动任务保障未明确；R6 历史 JT 保留不足；R7 既有流程图与 BOP 并行权威；R8 绑定临时编码缺乏长期身份；R9 多端冲突粒度过粗；R10 自管文件与 FCC 重复存储；R11 共享 UI 线程阻塞；R12 缩略图服务与权限能力未核实。

风险都需进入对应阶段的可验证探测，不以追加兜底重试、全量下载、自动近似匹配、全局锁住用户界面来掩盖。
