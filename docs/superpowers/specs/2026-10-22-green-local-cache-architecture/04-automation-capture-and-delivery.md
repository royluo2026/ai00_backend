# 04 自动化、租约、截图、上传与条件回填

状态：设计草案；正式版保留现有权限、确认及治理。批次授权只有在真实契约支持且范围明确时复用，不复制演示版跳过校核。

## 1. 执行计划

一次开始固定 `run_id, workspace_revision, model_set, snapshot_id, bop_ref, binding_revision, capture_policy_version, expected_dependencies`。由服务器／所有者生成有序工序列表；临时顺序号仅用于本轮，不成为持久关联键。

其中 bop_ref 必须包含工艺技术快照，绑定输入必须包含 binding_scheme_id 及精确 scheme_revision；仅业务标签或 binding 列表不足以开始任务。方案与当前工艺／配置不一致时拒绝执行；多适用方案未选择时要求选择，不按“最近一次绑定”推断。UI 切换方案不改已在运行的固定任务，参见 [09](09-process-auto-revision-and-multi-model-binding.md)。

每步含具体 process／requirement ref、目标实例集合、相关输入摘要、可执行状态与跳过原因、可用的原生批量指令及时间预算。缺失件、未知来源、无几何不能死循环；按策略明确跳过或暂停。

工序顺序来自固定工艺关系，不依赖当前 UI 折叠、卡片坐标或临时排序。倒序截图策略和标准正向工艺顺序分开记录。

## 2. 控制与租约

本机只有一个原生调度入口。云端执行授权、任务状态与本机文档租约相互绑定，但不是同一把锁。

租约字段：`device + runtime_instance + doc_session + model_set_scope + task + fence + acquired_at + expires_at + permissions_scope`。fence 单调递增；已过期或旧 fence 的指令、完成回报不得修改新任务。心跳丢失后不能无限延长本地执行。

实际租约时长必须兼容当前签名计划、原生超时和 runtime session，不在规格里擅自改变现有 600/660/900 秒等实现预算。只有测量并经契约修订才能调整。

截图独占相关视角、颜色、显隐及结构依赖；不锁住整个 App，不关闭其他原生进程。另一个文档的业务操作不被全局租约禁止，但原生共享线程仍需串行和拥塞提示。

状态命令：开始固定计划；暂停停止新原生步骤并等待／标识当前步骤边界；停止取消后续并保留已确认结果；重置恢复约定显示状态并显式处理本轮结果关联。不能把“取消已发出”显示成“原生已经停止”。

## 3. 单工序流水

`pending → native_running → image_durable → uploaded → attached`；旁路为 `skipped / failed_without_effect / outcome_unknown / conflict / cancelled`。

步骤：检查相关会话／依赖版本 → 设置目标展示 → 原生截图 → 临时文件校验 → 原子落盘并记入结果队列 → 完成本工序约定隐藏 → 下一工序。上传和回填消费有界队列，可以与后续原生步骤并行。

颜色、显隐只作用任务集合，初始底色／场景准备属于任务初始化，不每工序全量重置。是否需要可见性或遮挡校核由正式截图策略明确，不未经评审套用演示简化。

不强制正式版逐张卡片动画；UI 可按结果事件渐进显示，无需为展示效果阻塞原生执行。

## 4. 本地可靠结果

文件写到受控 `.partial` 路径，验证 PNG、尺寸、必要的非空检查和内容摘要后原子重命名，再用 SQLite 事务写入可上传状态。文件和数据库不存在跨系统原子事务，启动对账要处理文件已完成而索引未提交的孤儿；不能直接删。

结果身份绑定 `run + step + artifact content`。相同已确认步骤重试复用已落盘结果；原生 outcome unknown 不生成虚假成功，先检查可靠落盘证据和该步骤状态。

磁盘不足时暂停生产新图片，保留待上传文件；队列设置字节和条数上限，网络慢时形成背压，不无限占盘。具体上限由工作负载测试与用户设备预算确定。

## 5. 上传与附件幂等

先创建／获取上传身份，上传结果绑定摘要和资源范围。上传凭据仅短期保存，日志不带票据／密钥。重复请求不能创建多个不可区分的业务附件。

回填消费 `artifact_ref + exact process/slot + input dependency fingerprint + expected attachment revision + idempotency_key`，actor 由服务端确定。由 craft 所有者校验权限、工序仍存在、需求／绑定／模型依赖和附件槽版本，在单域事务挂接并审计。

不能由仿真 Provider 直接写 craft 表，不能用工序名称查找回填，不能覆盖整个 BOP JSON。若业务允许历史版只读，则回填到明确派生工作版本，不能破坏已冻结版本。

结果分开：已截图、已上传、已回填、回填冲突。上传完成不等于工艺卡已关联；工艺卡网络加载失败也不等于回填失败。

## 6. 崩溃与重试表

| 故障点 | 恢复行为 |
|---|---|
| 原生调用超时，没有可靠结果 | outcome_unknown，不能再次盲发相同副作用 |
| PNG 完成但队列未提交 | 对账文件及身份，恢复待交付状态 |
| 已落盘、未上传 | 只上传，不重截 |
| 上传已成功、响应丢失 | 通过幂等身份查询，不重复制造附件 |
| 回填已成功、响应丢失 | 查询相同请求结果／附件关系，不重复挂接 |
| 他人更新工序需求或绑定 | 标记冲突，保留图及旧依赖，明确重新执行或采用策略 |
| 文档关闭／模型集合变化 | 停止原生下发；已落盘交付可按原依赖继续或报告冲突 |
| 缓存清理 | 通过原生文件接口重新获取；不删快照、绑定或结果 |

## 7. 重置及补偿

正式版不清空整线历史图片。结果关联若需撤回，要按 artifact／relation identity 和 expected revision 调用所属能力；保留原文件、执行历史和原始 BOP 附件。

显示恢复是条件补偿，不是数据库事务回滚。若用户后来改变同一节点或视角，不能覆盖其状态；标记未恢复项。颜色与显隐、模型位姿、用户选择分别定义恢复策略。

## 8. 性能证据

记录本地调度等待、原生着色／显隐、截图、落盘、上传排队／传输、登记、回填。热态单工序 5 秒为设计目标，明确以原生执行到可靠落盘作为主指标；端到端回填另报。同时报 p50/p95、失败／跳过比例、样本与模型规模。

缓存命中不重复准备、队列不逐步询问下一动作、上传有界并发是结构目标；不能以减少权限或版本检查换性能。
