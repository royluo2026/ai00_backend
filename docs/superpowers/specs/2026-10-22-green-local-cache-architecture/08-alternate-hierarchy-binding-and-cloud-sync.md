# 08 备选层次结构、正式绑定回传与跨域云端同步

状态：详细设计草案；新增／变更契约需按真实 Catalog、Provider、域归属和消费者评审。本文描述 AI00 digital_model 域，不表示自动修改 Teamcenter 工程 BOM 或 JT 内容。

## 1. 编辑入口与三类关系

备选层次结构是零件／资源与工位、工序、操作绑定的主要工作台。树拖放后必须区分以下效果，不能因为显示在某节点下就视为已发布绑定：

| 关系 | 语义 | 权威归属 |
|---|---|---|
| 树编排／placement | 在工作树中组织、显示、放置模型或资源 | simulation |
| 正式工艺语义绑定 | 工艺／操作装配、使用、操作或其他已登记角色的具体对象 | craft 版本化绑定 |
| 模型身份与反向使用投影 | 哪个模型版本／实例被哪些正式工艺绑定使用 | digital_model 管身份并提供反向查询；关系来源仍是 craft |

树父子、场景位置、语义绑定分别保存。拖放动作有明确模式／角色；涉及正式绑定时展示目标工艺、需求、配置和角色，而不是根据位置隐式猜测。批量操作预览新增、替换、撤销、未识别项，明确原子或逐项提交语义。

## 2. 现状依据及差距

已读代码：前端 `packages/sim-plugin/web/cad_sim/cad_sim.js` 的模型／资源 placement 调用；后端 `plugins/simulation/simulation_backend/capabilities/alternate_hierarchies.py`、`data/workspace_repository.py` 保存树、BOP 来源及 source_ref，并使用版本和幂等校验。因此当前编排不是纯前端效果。

craft 的 `data/bop_collaboration_mysql.py` 已有 `workmanship_craft_bop_bindings`、`workmanship_craft_bop_binding_revisions` 及导入绑定路径；digital_model 的 `capabilities/models.py` 已有模型、不可变版本和 components。应复用这些事实，而不是再建一个独立可写绑定中心。

差距：当前 placement、`simulation_occurrence` 引用及模型版本尚不能据此证明形成完整的多配置、资源类型、正式方案、可靠跨域回传闭环；现有代码不是新规格已验收的证据。

## 3. 端点与关系记录

正式关系至少固定：

- 所属租户／项目、BOP 仓库及精确技术快照、工作空间／分支，禁止错误回写原始来源 BOP。
- 工位／工序／操作稳定身份、相关内容版本、具体零件／资源需求身份。
- 目标类型及权威身份；模型目标含不可变版本、配置快照、完整 occurrence key；运行时编译另明确模型集合。
- 资源目标含资源业务身份、适用版本／规格及需求角色；资源的可选几何表示另记，换显示模型不自动换业务资源。
- 方案及方案修订、binding_id／binding_revision、绑定角色、数量／单位（有业务要求时）、来源证据、操作者及状态。

原生节点号仅用于本轮解析，不能写成长期目标身份。相同 snapshot 在文档插入两次时，方案的工作场景装入映射必须明确集合，不因同文件或同零件号操作两份。

备选树节点保留 `source BOP snapshot + source process identity`；改名、移动不丢来源。由 Fork 派生时通过可信 lineage／映射定位当前工作对象，不能把 Fork 内新节点 ID 直接写回原 BOP。仿真自建无正式来源节点只能先为草稿，经显式工艺创建／映射后再提交正式关系。

未知模型来源、缺失实例或未确认自动匹配允许留在草稿；正式执行使用的关系必须满足契约。没有 JT 的合法资源需求可以正式绑定其业务对象，不能为了绑定工具业务身份强制要求几何存在。

## 4. 权威提交协议

1. 本地记录稳定 mutation_id、base revisions、精确变更集和内容摘要，立即显示“本地草稿”。UI 重试不能每次 Date.now() 生成新业务请求。
2. simulation 准备关联：校验工作树来源、方案、目标集合和已有选择，向所属域取得可验证端点版本；不跨域直接 SQL。
3. craft 接收正式提交，校验当前主体权限、准确工艺版本／需求、方案基版本、端点身份和绑定角色。不可变模型快照可避免目标内容在校验后原地变化，但删除／授权策略仍需验证。
4. 在 craft 单事务写绑定／方案修订、幂等结果、变更序号、审计及事务发件记录（或同等已有可靠提交日志）。不能先写主表、事务外再临时发送通知。
5. 返回 binding/scheme 正式身份、修订、摘要、提交水位及各投影状态。本地用正式记录替换草稿，不通过显示位置推测成功。
6. simulation、digital_model 和流程图投影幂等消费已提交变化。写投影不重新生成权威 binding_id，不修改模型工程版本；同步结果可查询并重放。

不是三次前端保存，也不声称跨数据库分布式原子事务。正式绑定一旦提交，投影失败不回滚成“从未保存”；状态改为已保存、同步待追平。

## 5. 可靠传播与反向查询

事件最小内容：`event_id, source_domain, tenant/project scope, aggregate_id, aggregate_revision, event_sequence, operation/mutation_id, committed_at, relation_revision_refs, tombstones, payload_hash, schema_version`。敏感凭据不入事件；跨域消费者仍按数据访问约定运行。

发件重试有界退避和持久待处理状态；消费者对 event_id 去重，按聚合修订单调更新。同一修订不同内容拒绝并告警；旧消息不能覆盖新绑定。撤销必须有墓碑，不能仅删除一行造成反向索引残留。

消费端事务内更新投影和确认记录。事件缺口、cursor 过期、投影丢失时从权威版本／变更日志按 scope 重建；保留 watermark 和差异对账能力。无需新增通用消息平台，优先使用已有事务日志与后台任务设施。

digital_model 查询返回“此精确版本／实例被哪些 BOP／工序／操作及方案使用”，标出关系版本、来源水位和投影完整性。读到过期投影时，查询权威关系或显示同步中，不能以空列表宣称未绑定。读取仍检查当前用户是否有权看相关工艺。

选择“云端已保存”后的读应支持 minimum revision／commit watermark 或权威回读，保证用户能读到刚提交关系；这不是保证所有异步投影瞬时一致。

## 6. UI 状态

`local_draft → queued/submitting → cloud_committed → projections_pending → synchronized`；异常分 `conflict / unresolved / authorization_failed / failed / outcome_unknown`。

离线仅保存草稿和待提交变更；在线重新验证权限／版本。请求超时按同 mutation_id 查询状态，不盲目重建一条绑定。云端保存、数模域同步、原生视图生效分别显示；主树出现条目或原生高亮不证明云端提交完成。

用户可查看错误作用于哪条关系并重试允许的阶段；不能在异步传播失败时反复执行已成功的权威提交。

## 7. 编辑、撤销与阶段影响

改绑定产生新修订；同方案互斥约束按角色定义，不把合法多工序使用一律判重复。同一 operation 绑定多个零件／资源是正常情况。

撤销通过权威变更及墓碑传播；冻结基线仍引用旧修订。原生删除模型只使工作场景映射／适用性失效，不自动删除正式工程绑定。更换数模版本生成新适配方案或方案修订，不把旧目标 UID 换成当前同名件。

## 8. 验收

- AB01：同件重复实例、TG0/TG1、同快照双集合均能唯一执行目标。
- AB02：树改名／移动、BOP Fork 映射后仍回到正确工艺工作对象。
- AB03：零件和资源分别保留 typed 身份；无几何工具需求可绑定。
- AB04：并发修改工艺／方案触发 CAS，不覆盖他人。
- AB05：提交成功响应丢失、重复点击、重复消息、乱序消息不重复绑定。
- AB06：digital_model 离线／消费失败仍保留权威关系，可重放追平。
- AB07：撤销有墓碑，其他设备／网页查询一致且不泄露无权限工艺。
- AB08：原生变化和本地断网不能把未确认草稿显示为云端已同步。

新契约的正式 ID、GID、资源权限、批次事务边界、绑定角色枚举和事件留存周期待所属域核实后登记；不能直接把本节字段当成已发布能力。
