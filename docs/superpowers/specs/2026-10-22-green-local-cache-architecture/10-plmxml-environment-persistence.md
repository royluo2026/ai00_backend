# 10 PLMXML、原生会话与环境保存恢复

依据：[Siemens 14.2调查及逐项来源](../../../architecture/green-local-cache/siemens-14.2-plmxml-research.md)。状态：设计提案；文档能力不等于当前安装、许可证或 COM 接口已通过实测。

## 1. 内容所有权与格式

simulation 拥有 EnvironmentRevision 和环境依赖 manifest；通过现有 Artifact 公共端口保存文件。craft 继续拥有工艺快照、绑定方案及正式语义绑定；digital_model拥有工程模型身份/版本，不从 XML 另建一份绑定主库。

环境记录固定 `process_snapshot_ref`、`binding_scheme_ref`、`model_sets`、`configuration_snapshot_refs`、`native_artifact`、`dependency_manifest`、`save_profile`、原生产品版本/服务级别、来源文档及原生 generation、完整性和验证证据。

原生场景优先采用可保存受支持扩展内容的 PLMXML。多文档工作会话可采用 VF；明确跨机/长期离线才生成 VFZ或经过验证的依赖包。不是每次同时生成全部格式。

复用现有 `plmxml_environments`、`environment_documents` 与Artifact边界；当前自建codec是结构语义投影，不能视为完整原生文档编解码器。原生原件与其派生投影分别保存/标记，不通过结构重建静默丢弃未识别扩展内容。需改引用时优先受支持原生另存/打包，不用通用XML重写器任意修改私有扩展。

## 2. 三类保存档位

| profile | 内容和约束 |
|---|---|
| structure_projection | 保持现有精简结构导出，供投影/映射；不表示已保存完整环境 |
| environment | 所选精确文档/集合的静态结构、受支持扩展内容及当前/指定视图，收集派生文件引用；普通模式不复制全部JT |
| portable_archive | 用户明确选择范围，经过配额/权限检查后复制完整所需依赖或原生VFZ；进入长期保存分类 |

Product View-only 增量仅在匹配结构上合并，固定 base_structure_hash，不能单独打开或自动套用到新配置。当前状态视图可在打开时自动应用，必须纳入场景generation变化及恢复测试。

## 3. 保存协议

1. 请求携带 workspace revision、DocSession、目标modelsets、profile、mutation_id、expected_revision和所需功能清单。
2. 获取匹配目标的本机短期操作租约；若保存偏好是应用级，序列化该应用的保存操作，不阻断用户任意长时间工作。
3. 确定静态/跟随配置模式、所选插入模型、快照/默认当前态、延迟视图处理和派生结果是否已保存；给出明确的范围与完整性。
4. 保存到受控暂存路径，生成文件/依赖manifest并校验完整性；不全量复制FCC，不从Renderer接收任意文件路径。
5. 对比保存前后的原生generation；有并发变更则标stale/重试或显式形成带边界的草稿，不封存混合状态。
6. 经受治理Artifact上传并由simulation以CAS提交不可变EnvironmentRevision；失败保留可靠暂存，可幂等继续，不能冒充已同步。

副作用中断为outcome_unknown，先查询保存/提交结果；不盲目重复另存或覆盖。临时偏好全部在finally恢复；native模态问题不能靠点击任意窗口解决。

## 4. 依赖与完整性

每项依赖包含业务文件身份/版本（若可得）、角色、原生引用、受控解析方式、artifact或精确TC文件引用、摘要（对实际保存字节）、大小和状态。角色至少区分geometry、clearance_results、markup/motion等派生文件和其他原生必需文件。

碰撞结果results.txt作为不透明原生依赖保存/重载，不解析未受支持内部格式充当业务API。检测输入、容差、引擎版本和结果所依赖几何/位置快照另外记录；换模型后恢复的结果不是自动有效结论。

相对路径/绝对路径/URL/需VVI解析的PDM引用分开。跨机包不能保留另一电脑临时路径作为唯一来源。路径解析不得越界，禁止XML外部实体及未经授权的网络读取；原生保存文件名采用ASCII生成名，显示名单独保存。

三种完整性独立：manifest/业务引用完整、几何和派生依赖可获取、原生往返恢复验证。文件上传成功不等于三者通过；未实测标unverified，缺项标partial/missing。

## 5. 恢复、冻结与性能

App重启先精确重接活文档，不无条件重开。文档丢失才恢复已存环境；重建的是native句柄映射，不重建业务绑定。相同文件的不同实例和重复插入集合必须保持隔离。

工作环境可显式跟随配置；TG0/TG1冻结必须用实际静态结构与精确引用。记录规则不代表冻结；恢复冻结版本不得默认切成configured/latest，不通过同名文件补旧版本。

完整环境保存不进入逐工序热路径。截图起始快照可用于恢复显隐/颜色，但须真实验证其范围，且不能撤回他人后续修改。上传/回填与原生保存分别计时。分别记录热态重连、场景冷恢复、依赖获取、结构映射、保存、上传、业务提交；不承诺PLMXML会消除几何加载成本。

## 6. TC和磁盘边界

AI00保存到云端Artifact不等于向TC保存ProductView。TC对本地模型、PLMXML来源和混合插入等场景有禁用条件，必须通过明确独立能力处理；默认不写回TC。

VFZ依据当前产品文档有容量/文件数限制；按实际JT和原生版本检验。日常环境/视图文档计入AI00场景数据，显式归档模型计入长期模型；待提交包计入可靠暂存。FCC仍单列且不可由AI00自动清理。

## 7. 原生验证门 V7 与验收 PE01–PE08

- PE01：旧结构导出兼容；新环境保存不得冒用原路径的成功状态。
- PE02：双集合、重复实例、源/场景矩阵、显隐、材质、相机、切面、活动备选树往返逐项核对。
- PE03：碰撞结果及派生文件可原生重载；缺失时报告依赖，不能悄悄丢失。
- PE04：静态TG0重开不解析成新模型；动态刷新必须新快照，不能改旧基线。
- PE05：活文档重接不下载/重开；丢失后恢复不重写业务绑定且旧句柄失效。
- PE06：偏好异常/取消/并发保存后恢复原值；源文档变化不能封存混合代际。
- PE07：跨机包移目录后验证完整性、大小限制和缺失文件；普通保存不重复复制JT。
- PE08：越界路径/XXE拒绝，上传/提交重试幂等，版本冲突保留结果，不覆盖他人环境。

V7失败仅限制未验证特性。可保留受支持原生VF回退或明确降级，不以“XML Schema有该元素”替代本机保存恢复证据。
