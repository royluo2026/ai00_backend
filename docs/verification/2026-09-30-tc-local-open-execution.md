## 已实现

- 共享准备产物、准备状态与 0036/0037 迁移；按固定版本保存 TC 文件引用、装配变换和排除原因。大产物压缩后以独立分块行存储，避免 MySQL packet 和 OceanBase CONCAT 长度限制。
- `vismockup.model.open@3` 与本地文件签名回执；新流程不依赖 OIS Artifact 或上传者回执。
- 客户端按当前 TC 身份和固定来源检查本地 SHA256/长度；缺失或损坏时下载，文件原子落盘。复用 FMS 工具。
- 复用单环境文档、装配根和世界坐标。旧包中的 JT 不覆盖；发现内容改变明确失败。
- 本机源文件缓存 7 天/10 GiB 清理；装配包 7 天后在原生进程已退出时清理。持久化进程身份保护，Connector 重启不解除保护。此策略保守保留同一原生进程内已关闭文档的包，直到进程退出。
- 页面不再请求旧 JT 获取/上传能力。旧 request 入口明确拒绝；真实 Connector 不再发布旧上传操作。
- Main 解析有界本机进度，调试日志记录阶段、计数和耗时；页面读取当前本机包进度，不将共用数据当作本机就绪。

- 供气装置：44 个 JT 首次本机无命中，准备约 34.7 秒；原生初次打开报 `vismockup_document_limit_unverifiable`。重试 44/44 命中后成功，78 个几何实例，全部与准备矩阵一致。该初次失败根因未确认，不能认为已修复。

- 切环境取消后悬架：在 UI 下载 3/55 时切换，Connector 在 5/55 后停止，签名终态 `failed_without_effect / cancelled`，原生仍为 117 个实例，没有迟到插入。
- 发现并修正取消重试缺陷：被导航打断的 job 仍保留旧 operation。下一次明确点击应先核对旧回执，只在其为 `failed_without_effect` 且错误 `cancelled` 时开始一个新请求；未知效果或已成功的旧任务不得重复执行。新回归先失败（旧 cancelled），修复后通过，真实日志 04:42:16.661 UTC 出现 `retrying_cancelled`。
- 真实后悬架首次重试成功，55 JT 中 5 个本机命中，新增 116 个几何实例；累计 233 实例，仍为 1 文档 / 1 根。新增 116 个世界矩阵与对应准备文件逐项一致（误差 <= 1e-8），原有 117 个世界矩阵完全保留。
- 期间遗留空文档无法通过 CloseDocument 完整释放，曾产生 `vismockup_dispatch_d4_h80020009` / outcome_unknown；未擦除执行记录或伪造终态，使用正常退出及正式恢复流程后继续测试。不能据后续成功宣称遗留文档恢复路径已经修好。
