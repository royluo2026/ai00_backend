# 绿标工程工作场景与本地缓存架构改造完整指南

版本：1.2；日期：2026-10-22；对象：正式绿标桌面端、网页端、云端及本机 Connector。

状态：用户已确认总体方向，本文是改造依据，不代表功能已实现、原生接口已验证或正式发布已通过。橘标只用于观察实现和性能，不是绿标业务规范。

新增依据：[Siemens 14.2官方文档调查](siemens-14.2-plmxml-research.md)、[PLMXML持久化规格](../../superpowers/specs/2026-10-22-green-local-cache-architecture/10-plmxml-environment-persistence.md)、[详细实施计划](../../superpowers/plans/2026-10-22-green-local-cache-architecture/README.md)。原生场景可保存结构与扩展会话内容，但碰撞结果等仍有独立依赖；静态冻结与动态配置恢复分开，原始文件与结构投影分开。

## 1. 业务目标与边界

把流程图、BOP、产品配置、数模、绑定、知识规则、问题、仿真、截图和回填作为一个可追溯工程工作场景管理。目标不是单纯移动缓存或把内嵌窗口改为外置，而是在多人、多端、多阶段和可变原生文档之间维持正确关联，同时减少重复获取和等待。

硬性要求：

- Teamcenter 负责工程配置解析；AI00 不仿制版本／变量规则解释器。
- 在线业务事实由各云端业务域负责；SQLite 是本地工作集、恢复及待同步结果，不是第二个权威业务库。
- 普通 JT 文件采用 Siemens FCC 缓存，不按项目、版本、配置默认复制完整文件包。
- AI00 自有数模存储仅包含用户明确通过 App 保存、供长期使用的数模；普通打开不自动归入长期保留区。
- VisMockup 默认独立窗口，支持副屏，用户正常旋转、选择、插入、移动、切换文档；AI00 保留自动化控制。
- 所有自动化精确到进程、文档、模型集合及实例，不独占全部进程，不默默操作当前活动文档。
- TG0、TG1 等基线冻结后不可原地修改；同一原生文档可装入多个阶段的独立模型集合。
- 流程图缩略图持久缓存，原图按需在线读取，不建立长期原图缓存。待交付截图是可靠暂存结果，不能提前清理。
- 生产数据、配置、缓存不得用于开发试写；实施先在隔离测试环境及演示数据副本验证。

## 2. 四层职责

| 层次 | 权威和内容 | 不承担的职责 |
|---|---|---|
| 工程来源 | TC 零件版本、配置规则、装配、实例、布局和文件来源 | 不代替 AI00 工艺与执行事实 |
| AI00 冻结事实 | 解析结果、BOP 精确版本、绑定、阶段基线 | 不依赖当前 PID、节点号或缓存路径 |
| 当前工作场景 | 从基线派生的工艺、模型集合、用户修改和未解决差异 | 不原地改写冻结基线 |
| 本机运行会话 | 文档、原生映射、加载状态、交互、任务执行 | 不成为长期工程身份 |

## 3. 身份链

必须区分 TC 系统来源、零件、工程版本、几何表示、精确文件身份、配置快照、配置内实例、模型集合、原生会话节点、工序及工序版本、流程图节点、GBOP 标准定义。

定位链：工作场景 → 模型集合 → 配置快照 → 实例 → 当前原生节点。绑定落在工序版本／零件需求与指定集合的实例之间，而不是零件名称、原生节点号或文件路径之间。

同一个 JT 可以被多个项目、多个阶段及多个位置共享；每个实例的位置、选择状态、绑定独立。原生 PID、节点号和缓存路径变化只影响会话映射，不应触发业务重新绑定或 JT 重新下载。

## 4. 流程图与 BOP

流程图分为业务结构、工艺语义关系和显示视图：

- 业务结构：线体、工位、工序、操作、零件需求及归属。
- 语义关系：前后置、分支、汇合及工艺关联；修改需要业务记录。
- 显示视图：坐标、布局、缩放、折叠、卡片样式；通常不影响模型绑定。

同一个 BOP 的多个视图引用同一组业务对象，不能各自复制工序形成互不一致的数据。历史流程图与 BOP 的映射必须调查及迁移，不能凭编码相同断言一致。

GBOP 编码关联标准工艺定义及版本，不代替具体工序实例身份。标准工序可能跨线体重复使用。临时数字编码仅作为迁移辅助；不完善的标准库留接口、记录未标准化状态，不阻断已有工序。

备选层次结构是主要绑定工作台，但编排 placement、空间放置和正式工艺绑定分别管理。正式关系沿用 craft 版本化绑定，simulation 管草稿／场景，digital_model 管模型身份及反向使用投影。云端权威提交与待同步事件可靠保存，数模投影幂等追平；本地草稿、云端保存和全部同步分别显示，不通过前端三次独立保存冒充原子提交。

用户业务发布版本与自动技术修订分开：有效工艺保存自动产生修订，重复请求／无变化不重复产生；布局和附件另记。已发布 A版不原地变化，修改显示为“基于 A版的未发布草稿”。同一精确工艺快照可有多份数模适配方案，执行明确方案及修订，后一次绑定不覆盖以前的方案；冻结固定这些精确组合。

仿真插入 BOP 明确记录来源版本、仿真使用版本／工作副本和指纹。源 BOP 更新不自动改变已插入引用；升级需要新工作场景版本和绑定差异处理。

## 5. TC 配置与冻结

在绿标提供：选择产品 → 查看／设置版本规则与日期 → 加载适用的已保存变量规则 → 显示生效配置 → TC 解析 → 打开指定模型集合。

同一配置贯穿结构读取、原生打开、实例映射、绑定和截图。记录规则 UID、可得定义指纹、产品／配置上下文、装配布局及有效性条件；规则名称仅供显示。

日期分开管理：配置／有效性日期、TC 解析时间、AI00 冻结时间。日期不是一致性令牌。冻结同时保存请求条件和实际解析结果，包括实例、工程版本、文件、位置、缺失与排除项。

冻结过程：固定 BOP 与绑定版本 → TC 解析并验证可证明的一致性 → 检查依赖未变化 → AI00 本地事务原子提交基线清单。不声称跨 TC 与 AI00 存在分布式数据库事务。TC 无法提供的历史一致性保证必须明确记录。

基线生命周期：准备中 → 已冻结／失败；修改从基线派生。允许冻结真实的不完整阶段状态，但必须列出缺失项，不能把未识别、未匹配说成已完成。

元数据可追溯和模型可重新打开是两个维度。长期重开依赖 TC 保留或显式受控归档，不依赖 FCC 永久保留。

## 6. 多阶段比较

同文档的 TG0、TG1 模型集合分别保留快照、实例、位置和绑定。比较分工程结构、空间／几何和工艺影响三层。

来源位置、仿真移动、比较对齐变换独立保存。比较对齐不改变冻结位置。实例对应优先可信工程身份和装配上下文；名称／几何相似只能辅助，不能静默确认正式绑定。

“TG0 工艺适配 TG1 产品”是新的分析场景：TG0 BOP + TG1 产品快照 + 新绑定迁移版本，不覆盖任一阶段。

## 7. 外置 VisMockup 与双向协作

外置模式停止渲染窗口重挂、隐藏原生主窗口、持续抢焦点、后台覆盖选择／视角和 App 退出时关闭用户模型。长期 COM 调用可能仍阻塞原生界面，必须实测并优化，不以外置等同于无卡顿。

连接明确目标 PID、启动身份、文档和模型集合。官方接口若不能精确连接多实例，应明确限制并寻找受支持方案；不得以关闭其他实例或操作默认实例冒充支持。

原生插入、删除、替换、移动同步为工作场景变化；来源不明的插入标为待识别，不自动归入 TC 快照或冻结基线。选择和旋转通常只更新交互状态，不产生业务版本。

事件优先、轻量差异检测补充；带来源和操作标识，合并通知、防反馈循环。首次连接、丢失事件或映射不一致时才做必要范围重建。

## 8. 并发、冲突与恢复

- 云端 BOP、绑定、工作场景使用乐观并发控制；附件变更不覆盖整份 BOP。
- 结构操作早期可采用线体范围的较粗版本检查；不预先建设庞大字段合并引擎。
- 本机 Connector 统一调度原生操作。短期租约限定文档和相关状态，具有过期、续期及 fencing 标识；过期执行者不能继续下发。
- 同进程 COM 串行约束与业务文档租约分别管理，不能承诺另一文档完全不受共享线程影响。
- 自动截图遇到相关原生结构变化、关闭文档或用户接管，暂停／停止。无法可靠判断变化来源时，不用过期映射继续执行。
- 恢复显示状态时不能覆盖用户后来做的新修改；冲突留给差异处理。
- 离线可以看已缓存版本；写回必须经过云端版本及权限检查。网页端与桌面端使用同一套业务冲突机制。

## 9. 本地加速与图片

流程图：SQLite 工作集 + 已保存布局 + 可视范围渲染 + 当前线体优先 + 云端增量同步。先显示可用版本，后台同步，不等待全量 BOP、所有绑定和图片加载完成。存在未提交修改时不得自动覆盖。

目标：已有工作集线体 1 秒内首屏可操作；首次无缓存不能承诺同样耗时。监测首屏、可操作、缩略图、后台追平时间，分别统计冷热状态与分位值。

缩略图按附件身份、图片内容版本、尺寸和访问范围缓存，使用云端生成／已有的适用缩略图。临时下载 URL 不作为永久身份。原图在线按需读取；不得承诺浏览器或系统从不产生临时缓存。

BOP 保留正式附件引用，不写本机文件路径。缩略图容量受控、闲置淘汰、账号权限隔离；离线可看已有缩略图，原图明确需联网。

## 10. 自动截图与正式回填

任务开始固定数模快照／集合、BOP、绑定和执行策略，预生成有序工序清单。原生连续执行，图片可靠落盘，上传有界并行，云端幂等条件回填；不每道工序重新查询和派发下一动作。

结果区分待执行、原生执行、图片落盘、上传、回填、失败、跳过和结果不明。已落盘不重复截图、已上传不重复上传、已回填不重复挂附件。原生结果不明不能认定成功。

重置仅处理本任务的显示状态与结果关联，不照搬演示版清空整条线图片，不删除原始工艺附件。流程图从正式附件关系接收更新，不依赖仿真页一直打开。

热态单工序按 5 秒目标实测，并明确包含的步骤；冷获取、加载、映射、上传、回填分别报告，不能只报最快样例。

## 11. 存储监控与状态栏

状态栏：本地占用总量 | AI00 容量 | VisMockup/FCC 容量。悬浮、键盘聚焦及点击可查看明细。

AI00 明细：用户明确长期保存数模、缩略图、SQLite 工作集／映射、待交付截图与临时输出。日志、语音资源、浏览器通用缓存另列，不冒充数模缓存。

FCC 明细：整文件、分段、索引；注明为 Siemens 管理。统计目录来自确认的有效配置或受支持信息，不能把默认示例当实际路径。

后台异步、限频、同一时刻单次扫描，不在悬浮时全盘扫描。总量排除重叠目录及可确认硬链接重复；区分逻辑字节与磁盘实际分配字节，无法取得实际值时明确口径。无权限、路径未知、部分统计显示未知／部分结果而非零。FCC 离线不等于目录占用为零。

同时展示相关磁盘剩余空间、最后统计时间、范围及错误。监控是只读；清理分别走所属机制，不能直接删除 FCC 内部文件。长期数模和待上传结果不参加普通缓存淘汰。

## 12. 变化影响矩阵

| 变化 | 失效／更新范围 | 可保留 |
|---|---|---|
| 卡片布局 | 视图 | 模型、绑定、截图 |
| 工艺文字 | 内容和相关规则／输出 | 无关几何映射 |
| 工序顺序 | 执行计划和相关场景结果 | 可确认的实例绑定 |
| 零件需求 | 对应绑定、相关截图适用性 | 无关工序结果 |
| 工序跨线／跨工位 | 归属、场景范围、计划 | 工序稳定身份 |
| TC 配置 | 新快照、实例差异、受影响绑定 | 未变化且可证明相同的引用 |
| 新附件 | 附件投影、工艺卡 | 工艺结构与模型配置 |
| 缓存淘汰 | 本机可用性 | 冻结事实和绑定 |
| 原生重启 | 会话与映射 | 文件缓存、快照和业务关联 |

过期不等于删除；保留历史结果及依赖版本。

## 13. 实施阶段与退出标准

1. 现状与原生接口验证：TC 两类规则、准确文档接入、事件、FCC 复用和文件可用性；产出能力矩阵，不臆造支持。
2. 共同身份与版本：跨流程图、BOP、产品、绑定和结果建立引用与版本边界；历史来源不完整的标记状态，不伪造。
3. 流程图关联：业务结构／视图分离、GBOP 接口、工艺—产品绑定及差异处理。
4. 外置双向协同：用户自由操作、目标精确、本机调度、差异与恢复。
5. 工作集与磁盘：增量同步、缩略图、FCC 主路径、长期模型显式保存、状态栏容量监控。
6. 自动截图闭环：有序本地执行、有界上传、条件回填、断点恢复。
7. 基线与联合比较：冻结、派生、同文档双阶段、工艺影响分析。
8. 灰度迁移：按场景启用，旧链路可回退；不全库破坏性重写。

阶段间按依赖交付小闭环；高风险原生探测先于不可逆数据模型承诺。每阶段的详细规格、接口、测试和回退另存，不把本指南视为可直接修改生产的授权。

## 14. 验收与证据

联合验收：流程图改工艺 → TC 选新配置 → 显示绑定差异 → 原生自由编辑 → 精确自动截图 → 云端附件回填 → 冻结 → TG0/TG1 联合比较；期间加入他人编辑、断网及各进程独立重启。

必须覆盖重复件、多实例、同名不同版本、配置相同名称但内容变化、原生未知来源插入、移动／删除、租约过期、事件丢失、上传响应丢失、部分缓存及权限撤回。验证无误用、无覆盖、无重复结果、无原图丢失。

本文不宣称测试或运行已通过。现状调查确认的仅包括安装包中的规则入口、FCC 组件及配置项、当前代码中的嵌入／隐藏机制和不完整的配置选择字段。多实例精确接入、原生事件覆盖、规则模式、缓存运行保障、历史重现及性能是待验证项。
